aos-tui: Markdown Rendering for Agent Replies

Models reply in Markdown, and aos-tui printed it raw. Users saw **bold**, # headings, fence markers and pipe tables as literal syntax. Agent replies now render in the terminal: headings, emphasis, inline and fenced code, nested lists, quotes, rules, links and GFM tables. Text wraps to the terminal width.

Result: 30 new tests pass, including a fuzz target, and go test -buildvcs=false ./... passes. Fuzzing found five bugs, all fixed (see Verification). No new dependency: the renderer uses only the stdlib and charmbracelet/x/ansi, which was already in go.mod. When stdout is not a TTY, the output is the raw text, byte for byte.

What Was Done

  • internal/tui/render/markdown.go: a line-based block parser and an inline renderer.
    • Blocks: ATX headings, fenced code (``` and ~~~), bullet and ordered lists with nesting, block quotes (nested, holding any block), thematic breaks, GFM pipe tables and paragraphs.
    • Inline: bold, italic, bold-italic, strikethrough, code spans, backslash escapes, [text](url), images and <scheme:…> autolinks.
    • Palette.AgentReply(prefix, body) is the entry point for final replies. Palette.Markdown(src, width) renders at a given width.
  • cmd/aos-tui/main.go: three one-word changes, from AgentBlock to AgentReply. These are the two printResult branches (yielded reply and WaitText) and the resume replay. AgentBlock stays as it was for the workflow progress feed, which prints one clipped line per event.
  • internal/tui/render/markdown_test.go: unit tests for each construct, plus a fuzz target and a regression seed under testdata/fuzz.

Design Decisions

QuestionDecisionWhy
StreamingRender the finished message once, at the three places that print it.StreamRenderer never prints reply text. Content tokens only feed the thinking spinner, and the JSON action that holds the message is parsed after the step ends. The complete text exists only once the step returns, so there is no partial block to re-render and nothing to buffer.
DependenciesNone added; no glamour, goldmark or chroma.AGENTS.md prefers stdlib. The subset models write fits in about 1,350 lines. x/ansi already provides grapheme-aware width and wrapping that keeps escape codes intact.
Parser strictnessLenient and line-based, not CommonMark.Anything unrecognised stays literal, so malformed input falls back to raw Markdown instead of dropping words. List items accept off-by-one indents, and a nested item under 1. needs only two spaces.
Line breaks in a paragraphKept.Replies use single newlines for layout, such as Name: x / State: y. Joining them as CommonMark does would merge those lines. GitHub comments keep them too.
The agent> prefixA leading paragraph shares its line and wraps around it. Any other leading block starts on the next line.This keeps one-line replies compact (agent> Done.), and tables, code boxes and lists stay aligned.
LinksStyled text, then the destination dimmed in parentheses. If the text repeats the URL, it is shown once.OSC 8 hyperlinks are not supported everywhere (macOS Terminal ignores them). Their escape codes would also have to survive wrapping and table cells.
Line breakingA line breaker of its own, built on ansi.DecodeSequence. It breaks at spaces and between CJK characters. Closing punctuation (，。）) never starts a line, and opening punctuation (（「) never ends one. Latin words and URLs stay whole unless one is wider than the line. Code blocks still hard-wrap.ansi.Wrap breaks only at spaces and hyphens, so a run of Chinese counts as one word. A live session showed the effect: the run either jumped to the next line and left the line above half empty, or was cut at an arbitrary point.
Styles across wrapped linesEach line closes its open styles and the next line reopens them.Indents, quote bars and table borders are added in front of each line, so a style left open must not colour them. A test checks that no rendered line leaves a style open.
Control charactersIn TTY mode, C0, DEL and C1 controls show as glyphs (ESC as ␛). Invalid UTF-8 shows as U+FFFD.Replies can quote web pages and tool output. A raw ESC ]52 can write the clipboard, and ESC [2J clears the screen. This also keeps width measurements exact. Non-TTY output is unchanged.
CostLinear time on unbalanced input.Backtick runs and bracket pairs are indexed once per inline text. Missing emphasis closers are remembered, and inline nesting is capped at 16 levels. 200 KB of unmatched [, <, * and backticks renders in about 0.1 s.

Verification

  • Per construct: headings (including #hashtag and C#), each inline style, nested emphasis restoring the outer style, and non-emphasis left alone (snake_case_name, 2 * 3 * 4, ~5, unclosed ** and backticks, escapes). Also links, images and autolinks; paragraph line breaks and wrapping; fenced code with tabs, long lines hard-wrapped, and unclosed fences; bullet and ordered lists (nesting, right-aligned numbers, hanging indent, lazy continuation, fences inside items, loose items); quotes; rules; and tables (alignment, CJK and emoji widths, ragged rows, escaped pipes and pipes in code spans, shrinking to fit).
  • Passthrough: with a disabled palette, Markdown and AgentReply return the input byte for byte, including CRLF, tabs and trailing newlines.
  • Wide characters: CJK text without spaces wraps to the width and nothing changes when the lines are joined back. A Chinese sentence from a live session fills each line before the next CJK character, and no line starts with closing punctuation or ends with opening punctuation. Latin words and URLs inside Chinese text are never split. Table rows with CJK, Korean and emoji cells all have the same display width.
  • Malformed input: 17 broken inputs, among them mixed fences, unclosed links, deep quotes and lists, over-long ordered markers and a 900-delimiter run. None loses a word.
  • Fuzzing (FuzzMarkdown, any input, widths 12–111). The property: every letter and digit in the source appears at least as often in the output, leaving out link destinations, which a self-link shows once. The final runs made 50.5 million executions in 5 minutes, then 6.3 million in 2 minutes after line breaking was added, with no failures. Fuzzing found five problems, all fixed:
    • A list item kept its own marker in its body, so the item recursed forever.
    • Invalid UTF-8 merged with the grapheme next to it during wrapping.
    • Raw escape sequences passed through.
    • Words after the first one in a fence info string were dropped.
    • An escaped backtick next to a code-span run sliced out of range. Its input is kept as a seed.
  • go vet is clean, and go test -buildvcs=false ./... passes.

Limits and Follow-ups

  • Not supported, and shown as literal text: setext headings (===), indented code blocks, reference-style links, inline HTML and task-list checkboxes. Code blocks have no syntax highlighting.
  • A table with so many columns that they cannot each keep four cells overflows the width, and the terminal wraps it. No text is lost.
  • Not checked in a live terminal session against a real model. The samples above come from the renderer itself.
