The Header Says the Agent Index Is Partial

Eval's A1 header re-test (c0c3471) had 306 A1 answers.

  • None of them called read_memory artifact_id=… for the lines the header hid.
  • Wrong answers clustered on negative claims, such as "8x8 was never measured". The line stating the fact was hidden, and the agent answered from working memory without a memory call.
  • The header called the index "a map, not the record". It never said the map is incomplete.

This change adds one variable: a short note in the header. It is one commit on top of 6c55bdb.

Result: go vet ./... and go test ./... are clean. With the note off, the header is 6c55bdb's byte for byte. RecallOff() is still byte-identical to the golden prompts. The effect on the probes is unmeasured until eval runs both arms.

The Note

The note follows the existing sentence that introduces the agent index, on the same line. It appears only when the header shows at least one index line.

PartShown whenText
S1Any agent-index line is shownThis index is partial: a fact missing from it may still be in the archive. Before you answer that something was never done, measured or seen, search_memory for it.
S2Some segment shows only its first lines, i.e. a "+K more" line is in the headerSome segments show only their first lines; "(+K more lines ...)" marks the rest, and read_memory artifact_id=<segment> returns the whole index.

The note adds no tool and no mechanism. The "+K more" line, the line selection and the 6 KB budget are unchanged, and the note's bytes do not count against the index budget.

S2 is not shown for a segment that shows no line at all. That happens only when even the "+K more" lines overflow the budget, at about 85 segments.

The Switch

  • Runtime: RecallPolicy.NoPartialIndexNote, JSON no_partial_index_note in a workflow spec's recall. Zero means on, as for the other aids. It matters only with the agent index (a1) on.
  • RecallOff() sets it, so "every aid off" stays true. A workflow with no recall block gets the note.
  • Trace: memory.header records agent_index_partial_note and agent_index_shortened_note (1 or 0), beside the per-segment shown and hidden counts.
  • Probes: a new aid name, a1p, for aos probe-memory --recall. memprobe and cmd/aos/probe.go live on eval's branch, so this is a patch for eval to apply: memory-recall-partial-note/memprobe-a1p.patch. Its contents:
    • a1p clears NoPartialIndexNote. memprobe's policy starts from RecallOff(), so --recall a1 alone is still c0c3471's condition, and --recall a1,a1p is the new arm.
    • The condition reads recall=a1+a1p.
    • Each sample records agent_index_partial_note and agent_index_shortened_note.
    • A test, TestProbesNoteThatTheIndexIsPartial.
    I tested it in a throwaway detached worktree of 7d055e8, with this commit applied: go vet ./... and go test ./... were clean. Eval's branch itself is untouched.

Does read_memory Return the Whole Index?

In a real run, yes. read_memory artifact_id=<segment> returned the segment's stored index, every line, as agent_index, on every page. That was tested only for the first page, so the test now reads a later page too.

In eval's probes, no. --agent-indexes, which the A1 probes use, puts the given index on the checkpoint's segment refs and leaves the segments unchanged. The header showed the given index, but read_memory returned none, so S2's pointer would have led nowhere.

Fix (runtime): read_memory now returns the index from the segment's ref in the session, the same source the header draws from, and falls back to the segment's own index when the ref has none.

  • In a real run, the ref's index is the segment's (both are set at the cut), so nothing changes.
  • In a probe, the given index now reads back too.

The new test fails without the fix.

Tests

  • TestHeaderSaysTheIndexIsPartial (agentflow) covers:
    • S1 alone when nothing is hidden, and S1 + S2 when an index is shortened. Both are pinned as literals and placed after the intro sentence of 6c55bdb's header.
    • With NoPartialIndexNote, the header equals testdata/header-6c55bdb/{whole,shortened}.txt byte for byte. Those files were written by 6c55bdb's code before the change.
    • No note with no agent index, or with a1 off.
    • The trace's two flags in each case.
  • TestWorkflowRecallReachesPromptAndRuntime: no_partial_index_note decodes from a workflow file. The spec's whole RecallPolicy reaches both the backend and the runtime.
  • TestAgentIndexIsStoredWithItsSegment:
    • a later read_memory page returns the whole index;
    • a checkpoint whose ref carries an index the segment lacks reads back the ref's index;
    • the base checkpoint is chosen as one holding the segment, because the first draft picked by store order and was flaky.
  • TestRecallSwitchesAreIndependent: RecallOff() sets the new field.
  • TestRecallOffKeepsThePromptsAsBefore: unchanged and passing.
  • Eval's patch: TestProbesNoteThatTheIndexIsPartial covers:
    • a1 alone gives no note;
    • a1 + a1p gives S1 without S2;
    • a shortened index gives S2;
    • each sample's flags and condition;
    • after the header, read_memory returns the given index, including the hidden line.

Not Changed

  • The "+K more" line, the line selection, the budget, the handoff logic and the golden prompts.
  • Eval's branch, internal/memprobe on main, probes and patterns.
  • Nothing pushed, and nothing run on phg-gpu.
