Hiding Service Sockets from Confined Commands

A test of ways to stop a confined Linux command reaching the user's service manager. Nothing in aos changed. The rules under test are the shipped helper at 2d7c390, with each candidate wrapped around it. No unit, Ray job or kernel was started.

Superseded on what was built: the recommendation here was built in ab0950b, with the escape proof, in reports/sandbox-socket-key-signal-fix.html. The statement below that systemd-run was not tried describes this test only.

  • A seccomp filter works here, with no privilege and no new dependency: systemctl --user goes from answering to Operation not permitted, and cuInit, nvidia-smi and nvcc still work.
  • Denying all Unix sockets breaks CUDA: cuInit returns 304, because CUDA itself makes two AF_UNIX seqpacket sockets. The filter must allow that one type, at least under allow_gpu.
  • Not measured: a real kernel. Only cuInit and cuDeviceGetCount ran, because allocating needs the offload window. systemd-run was not tried.

Every row keeps the shipped Landlock rules underneath. "Refused" means the call returned an error and the probe saw it. A hidden-path approach is a list of what to hide, and sockets can be anywhere the user can write: Ray keeps its own in /tmp, for example.

2. Why seqpacket is a narrow allowance

A SOCK_SEQPACKET socket connecting to a stream listener gets protocol wrong type for socket. That was measured against the user bus, systemd/private, the system bus and a test socket. The machine has 85 stream listeners, 17 datagram and 3 seqpacket:

Seqpacket listenerWho could connect under the shipped rulesUnder seqpacket-only with abstract scope
/run/udev/control, root, mode 600No one but root, by file modeSame
Two abstract @cuda-uvmfd-…, in other users of the cardA same-kind test listener was reachable, so these should beA same-kind test listener was refused

I did not connect to those two: they belong to the speech service and Strata, and the test used its own listener of the same kind. What is left open is any seqpacket listener at a path the user can write to, including /tmp/nvidia-mps/control if MPS is ever started. None was running.

What CUDA asks for, traced unconfined: a seqpacket connect to /tmp/nvidia-mps/control (absent), and a seqpacket bind and listen on its own abstract @cuda-uvmfd-…. nvidia-smi makes no socket calls. CUDA's own listener still works under the abstract scope, since the scope only stops reaching out of the domain.

The last row fails with or without the filter, so it is a limit of today's sandbox and not caused by it. The cause was not investigated. The checklist is small. A real workload that needs a Unix socket would need a grant, which does not exist yet.

The filter also denies, as an error and not a kill: any foreign architecture, so 32-bit binaries; x32 numbers; io_uring_setup, _enter and _register (io_uring is enabled on this kernel); and datagram socketpairs. Stream and seqpacket socketpairs stay, because they are already connected: re-pointing one with connect was refused every time, and sendto with an address on a seqpacket pair succeeded, which should go to its peer. That last point is from the kernel's behaviour as I understand it, not separately measured.

4. A better answer exists, on a newer kernel

This machine runs 7.0 with Landlock ABI 8. A Landlock right for exactly this, LANDLOCK_ACCESS_FS_RESOLVE_UNIX, is ABI 9, and appears to first ship in 7.1 (documentation patch; the release number is inferred from a v7.1 mirror, not from release notes). It would allow-list socket paths the way files are. The filter is what works on this kernel, and aos could prefer the right when it is present.

5. Recommendation, not built

  • Apply the filter in the confinement helper, after Landlock and before exec, on every confined command, and refuse the run if it cannot be installed.
  • Allow socket(AF_UNIX, SOCK_SEQPACKET) only when the policy has Devices. Otherwise no AF_UNIX socket at all.
  • Allow IPv4 and IPv6 only when the policy has network. That also closes the UDP gap in the current sandbox notes.
  • Add the abstract scope to the existing ruleset.

All four were measured only from outside the helper. Unit tests, mutation evidence and a kernel run in a window would still be needed. The filter here is x86-64 only, and an arm64 build would need its own numbers.

6. Limits of this test

  • Tried once, on one machine, on kernel 7.0.0-38. No repeated trials.
  • That the bus was reachable is shown by systemctl --user answering. That it can be used to escape is still inference: systemd-run --user has not been run.
  • The filter wraps the helper instead of being inside it, so filter and Landlock are in the opposite order from the recommendation. Neither should depend on the order, and that has not been tested.
  • Inherited socket descriptors, signals, and API keys in the environment were not tested. macOS was not tested.
  • The temporary folder on the machine has been removed. The one failed user unit there, a snap firmware notifier, is not from this test. No run-* unit exists.
