Memory Phase 2 Report: Retrieval

Phase 2 of memory-system-design.md. In the phase 1 baseline, an agent asked why leaf2 was dropped got the verdict right and the reason wrong every time. The reason sat past the first 64 KB page of a segment, and both agents that read memory picked a nested copy instead. Phase 2 lets an agent find a fact by searching and read it by message number. It also replaces the per-segment prose summaries in the prompt with an index of recorded facts.

Result: "why leaf2 was dropped" went from 0/9 to 8/9, reading about 4 KB on average instead of 32–43 KB. That change is real (Fisher exact, p = 0.0004). An archive-only question went from 8/9 to 6/9, which is no detectable change at n=9 (p = 0.58). Its misses do show a mechanism: the agent reads a narrow range and can stop at an intermediate result.

What Was Done

  • search_memory query limit? (internal/runtime/retrieval.go).
    • A message matches when it holds every word of the query, in any order. | separates alternatives, and re: takes a regexp. All matching is case-insensitive.
    • Hits that match more alternatives come first, and the newest comes first among equals. Each hit shows its message number, role, segment, archive time, and about 150 characters on each side of the match.
    • The result opens with a line that states only what the runtime knows, the order: "A higher # is later, not necessarily right: a later message can repeat or explain away a mistake. Check what a claim rests on." It is capped at 8 KB and says how many matches it left out.
  • read_memory from to?
    • It returns whole numbered messages up to 32 KB, with next_from when the range continues. The text then ends with a line such as "(stopped at 32 KB; #113-#115 not shown: read_memory from=113 to=115)".
    • A single message larger than the cap is cut. The result gives the artifact_id and byte offset where the rest continues.
    • A range outside the archive is an error that says which numbers the archive holds.
    • artifact_id/offset paging still works.
  • Ownership and nesting. Both tools read only the segments in the session's own refs, each checked with ownedBy, and both are always allowed. Each result is archived as a one-hop reference, never as a copy.
  • Old archives.
    • Segments written before numbering are numbered the way their checkpoint numbers live messages.
    • A read_memory result that an old segment copied whole is read back as the reference it would be archived as today. This applies to search, range reads and artifact_id reads, so the art-001074 copy that misled the baseline is no longer a second source.
  • Header index instead of summaries.
    • Each MemoryRef records its message range, archive time, tool counts, and up to six paths passed to read_file, write_file and edit_file, all at compaction.
    • Old refs are indexed once, before their next prompt.
    • The prompt shows one archive line, how to search and read, and one line per segment. It also states the index's limits: it is not a summary, and files that run touched are not listed.
    • Segments no longer store prose summaries, and memory_refs is gone from the header JSON.
  • Probe harness also counts search_memory calls and the bytes they return.

What the Probes Changed

Matching and ranking above are not what the design first said. The design said substring search, newest first. Two probe runs showed why that fails.

  • Run 1 (substring). The model wrote tridata order|leaf emission order|tri order, meaning alternatives of loose words. A literal match found nothing in an archive that says "TriData in tree/leaf emission order", and the agent answered that it had no record. Plain queries now match all words, with | separating alternatives.
  • Run 2 (all words, newest first). A broad alternative such as "tri order" matched 49 messages. The 10 newest crowded out the older message that held the measurement and matched the whole query. The agent then said "no decisive measurement was ever recorded". Hits are now ranked by how many alternatives they match. Each hit keeps its message number, so ranking does not hide which fact is current.

Both changes have unit tests and mutation checks. The runs are kept as v1/ and v2/ under reports/memory-probe-phase2/.

What the Numbers Mean

  • The target moved. Eight of nine phase 2 leaf2-speedup answers found "leaf2 is biased: RMSE 0.79, a build that dropped half the triangles" with a single search and gave it as the reason. Phase 1 answers gave the right verdict with an invented reason.
  • Narrow reads can stop short (qualitative; the TriData score itself shows no detectable change). TriData's answer spans two A/Bs, at messages 101–112 and 113–115. Phase 1 read a whole 64 KB page and got both by chance. Phase 2 agents read about 10 messages around a hit. Two of the three misses asked for ranges ending at message 112 and reported the first, inconclusive A/B ("4.6% slower, rejected"). The third read the wrong area. None was cut short by the 32 KB cap. Search finds where a topic is; it does not tell the agent where the decision is. Phase 3 is meant for this: a keyed working-memory entry written when the decision is made ("TriData tree order: no win, reverted").
  • A trade-off: removing summaries made one answer costlier, not wrong. tg-sweep was answerable from the old 180-character summary in one step. It now takes about four steps and 19 KB of reads. Removing the summaries follows the imitation lesson and the no-fabrication rule. The old summary also kept only the first six items of each kind, so whether a fact appeared in it depended on where in the segment it fell. Phase 3 should measure whether working memory recovers the cost.
  • Live controls stay cheap. w4-first-ab used no memory tools. leaf2-status averaged one search, about 3 KB, and stayed correct.

Review Fixes

The book session reviewed commit ecb29d4. Its main finding was the first wording of the precedence line: "a later message (higher #) supersedes an earlier one". The runtime knows only order, not truth, and the memfix run has three counterexamples, each a later message contradicting an earlier, correct one:

  • the round-8 coordinator's claim that the leaf2 rejections were on different node layouts;
  • the round-3 "CONFIRMED HUGE WIN", written after the bias finding;
  • the writer log's invented explanation for why leaf2 had helped.

The line now says a higher # is "later, not necessarily right", and asks the agent to check what a claim rests on. Phase 3's working-memory precedence is a different claim, about which record the agent maintains, so it stays.

Other fixes from the review:

  • The TriData result is stated as no detectable change (p = 0.58), with the narrow-read mechanism kept as qualitative evidence.
  • The cost of removing summaries is recorded as a trade-off for phase 3 to measure.
  • A cut range read now ends its text with where it stopped and how to read the rest. No TriData miss had been cut short, so this did not cause any of them.

The re-run also turned up a scoring false negative. An answer said the bug "silently dropped" the second triangle, leaving the BVH "missing roughly half the bunny", and the leaf2-speedup pattern did not accept those phrasings. The pattern now does. Every run was rescored with it: phase 1 stays 0/9, and no earlier phase 2 count changed.

Each mechanism was mutation-checked against its test: ownership, ranking, the tie order, all-words matching, alternatives, the result limit, whole-message paging, the cut offset, both archived references, old-ref indexing, implicit numbering, copy reduction, and read_file paths. Every mutant failed its test. Two first survived, and their tests were strengthened: a reread of the written file hid the read_file path, and a small sort happened to keep newest-first order. The full suite passes.

Not Done Here

  • Working memory, the pre-compaction handoff, and superseded-entry marks in search are phase 3.
  • No live rerun of the path-tracer workflow on this binary. The probes measure retrieval on the old run's archive.
  • Phase 3 should add evidence pointers to working-memory entries. The memfix run showed a durable ledger can hold a confabulated reason, written by the agent that forgot the real one.
