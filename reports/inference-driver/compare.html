Strata and Sonnet 5.5 on One Workflow

The same workflow (live-reviewed-merge), the same inputs and the same flags, through two model profiles. Each trial ran once on a fresh state directory with a 250,000-token budget and a strict 15-minute time budget, and passed only on review_partner's verdict. Every figure here is read from the trials' call ledgers and results; cached and cache-write tokens are what the servers reported. Dollars are the Anthropic calls' cost at $2 input, $10 output, $0.20 cache reads and $2.50 cache writes per million tokens.

How the replies were read

Each step's reply read the way the step read it (agentflow.ReadReply and ResolveRecordedReply), so the rungs are the D3 probe's: how the object was found (as sent, the trailing object after prose, or the loose repair), the shape that read it (nested, generic, flat, legacy), or a later rung (a repair, fallbackMessage, notesAsMessage, unrepairable). A misread is an action a person reading the reply would not have taken from it: a later object taken over the first, an action from inside a <think> block, or an incomplete action from the flat stage.

Reasoning recorded is the thinking a server returned apart from the reply and the ledger kept: the Anthropic driver records it. The chat-completions driver, not streaming, reads only the reply, so a reasoning model's thinking there is dropped; the last column estimates what was dropped, at four characters a token.

The HTML's way to the file

merger returns the HTML in a message action, delivery_lead hands it to file_writer in a goal, and file_writer writes it. Intact means file_writer wrote exactly the bytes merger sent and the file holds exactly what was written.
