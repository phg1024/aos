A1 Fix: Handoffs That Leave an Index

In eval's live run, only 5 of 27 handoffs left an agent index in their segment. Eval's breakdown named four causes:

  • 8 indexes were refused for size, at 1566–2684 B against a flat 1536 B cap.
  • 7 were refused because one line cited a message past the notice's range. In 23 of the 27 handoffs, the archive itself went past the range the notice named, because compaction recomputed the cut.
  • A refusal never earned a step to retry in.
  • 7 handoffs never called index_memory: the notice asked for working memory first.

This change fixes all four, in one commit on top of 68538ea.

Result: 4 new tests pass, and so does the existing suite (go test -buildvcs=false ./internal/... ./cmd/...). With every aid off (RecallOff()), the prompts and behaviour are unchanged, checked by the existing golden and pinned tests. Whether agents now index more handoffs is unmeasured until eval reruns.

What Changed

#ProblemChangeTest
1The notice range was not the archived range. The notice named the cut at notice time. At compaction, compactionCut ran again on a history that had grown during the handoff, and moved the cut later. With the index on, compaction archives exactly the messages the notice named: the cut is the message whose number is the notice's through. History that grew during the handoff stays live. If the history is still over the trigger, the next handoff archives it, under its own notice and index, so nothing is archived unindexed. With the index off, the cut is still recomputed as before. TestHandoffArchivesWhatTheNoticeNamed: the archived from_seq–to_seq equals the notice's range, after the history grew past the target. With RecallOff(), the same script still archives past the notice, which shows the scenario exercises the old cut.
2One bad line sank the whole index. Each line is checked on its own. Good lines are kept. Lines that are malformed, out of range or past the cap are returned in rejected with a reason each, and a notice asks the agent to resend every line it wants kept, fixed. Only an index with no good line is refused. A call still replaces the previous index. The index is final at the cut, when it is written into the segment, which is never rewritten. So there is no merging across calls and no later edit: what the segment holds is exactly the agent's last accepted call. The report of rejected lines is held to 1 KB and quotes at most 120 B of each line, so a retry step sees a bounded report. TestIndexKeepsGoodLinesAndRetries: one call has 2 good lines, 1 out of range, 1 malformed and 1 past the cap. It keeps 2 and reports 3, each with its reason. The retry's 3 lines replace them and are what the segment stores.
3A refusal did not earn a retry, so the handoff compacted. A memory write (index_memory or update_memory) that was refused, or had index lines rejected, earns exactly one more step, once per handoff. The step is given past both the step limit and the 16 KB bound, so a handoff takes at most maxHandoffSteps + 1 = 5 steps. The retry step sees exactly what the refused step saw plus two messages: the refused call's record and its report of at most about 1.1 KB. The record is the model's own output from that step, so the model's output limit bounds it. A second refusal ends the handoff. TestRefusedIndexGetsOneRetry: a 24 KB index with no valid line is refused, which takes the history past the 16 KB bound (the refused step was shown 13,622 chars; the call's record is 25,082 and its report 1,116). The retry step is still given, sees exactly those 2 extra messages, and its index is kept (handoff_end=overrun after it). A second refusal compacts with no index after 2 steps. TestHandoffOverrunIsBounded still holds.
4A flat 1536 B cap, which 8 indexes overran by up to 1.1 KB. The cap is SegmentIndexCap(n) = clamp(64 × n, 1536, 4096) bytes for n archived messages. A line runs about 50–120 B, so 64 B per message allows roughly a line for every one or two messages. Short segments keep the old 1536 B cap. The 4096 B ceiling (MaxSegmentIndexBytes, the name eval's memprobe already checks against) is two-thirds of the header's 6 KB total for agent indexes (agentflow.MaxAgentIndexBytes). So the newest segment's index always fits whole, and older indexes fall back to their pointer line as before. All of eval's refused sizes (≤ 2684 B) fit once a segment has 42 messages or more. A line past the cap is rejected, with the earlier lines kept, not the whole index refused. TestIndexCapScalesWithTheArchive: floor, scaling and ceiling, and the notice states the cap.
5The notice asked for working memory first, and 7 handoffs never indexed. With the index on, the notice asks for the index first, with its range, the rule that lines cite only that range, and the cap in bytes. Working memory comes second. The W4 reminder, when the index is what is missing, says you have not indexed it and names index_memory, the range and the cap. It adds the working-memory request when that is missing too. With the index off, both texts are as before. TestIndexCapScalesWithTheArchive (index first) and TestHandoffArchivesWhatTheNoticeNamed (the reminder names index_memory, the range and the cap).

6. Did the 16 KB Bound End Handoffs Early?

Eval's event data is not on this machine, so the code settles some cases but not all of them.

  • Before this change, handoffContinues checked historyChars > MaxChars + 16 KB before it gave any later step. A refused write never set HandoffWrote.
  • Refusal in the first handoff step: the step limit (4) cannot fire yet, and the W4 reminder is still unused. A missing index counts as "missing", so the only way such a handoff compacted without another step is the 16 KB bound. For this case, the hypothesis is confirmed by elimination.
  • Refusal in a later step: the handoff also ends when the reminder was already used ("no write"). Only the events can tell these two apart.
  • To make that readable from now on, memory.compacted records handoff_end (step_limit, overrun, wrote, no_write or other_action) and handoff_retried, whenever the index is on.
  • After this change, a refusal earns its retry whichever bound would have fired.
