Supervision Step 4: A Restart Policy in agentflow

This is the last step of the slice in supervision-design.md, for N5 and the review's gap 1.

  • A workflow agent can carry restart: {max, within, backoff}.
  • A retryable exit is recovered from the checkpoint the exit names, through the exclusive Recover.
  • More than max restarts within within goes to the delegator as a final exit.
  • internal/supervisor is now that policy, on aos run's path.

Result:

  • go vet, go test ./... (25 packages) and the audit probes pass.
  • Eval's three ca78ad9 trials replay identically.

1. The Policy

{"id": "worker", ..., "restart": {"max": 3, "within": "10m", "backoff": "1s..30s"}}
  • Absent: nothing changes, and a retryable exit goes to the delegator as it is.
  • Fields left out take the defaults shown above. "restart": {} is bounded, and no setting removes the bound.
  • Backoff doubles from its base on each restart in the window, up to its maximum. A single duration is a fixed wait.
  • An invalid policy fails spec validation, naming the agent.

2. What the Engine Does

Engine.supervise runs after every runAgent and resumeAgent, so it covers the entry agent and delegated children alike. It acts on a retryable, non-zero exit that is not a wait, and only while the run is live, so a SIGTERM stop is never restarted.

  • On success, supervisor.restart is recorded on the successor before its first step. It holds predecessor, attempt, checkpoint, backoff and reason. process.superseded links the two processes.
  • What the successor continues: the checkpoint's usage, and the same account chain. It also takes over the predecessor's leases and mail, and hears about the calls the predecessor left unfinished.
  • Escalation is a final exit reported to the delegator. The last process's kernel record keeps its retryable exit, because an exit is never rewritten. An operator may still Recover it on purpose; the engine will not, and it never restarts the delegator.
  • The intensity window counts the supervisor.restart events on the process's resumed_from chain, as recorded. It therefore holds across a wait and a resume, and across a new engine on the same directory. A fresh delegation starts a new chain. Fixed after review: c578edf kept the count in a local slice, so each resume started a fresh window. Both new tests fail on c578edf.
  • Review of v0.1.3: fixed after review: a short window disabled the bound, and a failed handover could lose an interrupted call. Every policy now also has a total. See supervision-review-fixes.html.
  • Concurrency: a delegated child runs inside its delegator's delegate step, one at a time. A backoff therefore holds up only the delegator that is already waiting for it.

3. internal/supervisor: Reduced, Not Retired

  • Deleted: RunChildren, a scheduler-driven loop that respawned fresh processes with no checkpoint, backoff, intensity or budget, and Tree. Nothing imported either.
  • Kept: RestartPolicy, its defaults, Backoff, and the intensity window (Recent, Exceeded).
  • Why reduce rather than retire: agentflow imports what is left, so the package named "supervisor" is now what supervises agents in aos run.
  • internal/scheduler has lost its only importer and is left in place.

5. Replay

  • A run with a restart has two processes for one agent, which replay does not handle. Replay refuses it (exit 2), naming the restart: it restarted an agent (supervisor.restart of pid-… as pid-… at evt-…).
  • So the backoff and the intensity window do not need to be reproduced. They use Engine.Sleep and the kernel clock anyway.
  • Records without restarts replay as before. All the existing legacy handling still applies.

7. Behavior That Changed for Existing Workflows

  • Nothing, for a workflow without restart.
  • The engine's traces and its agent_run follow a recovered successor's PID. This can only happen with a policy.
  • internal/supervisor's old API (Supervisor, RunChildren, Tree) is gone. It had no callers.
  • New runtime APIs: RunOptions.OnRecovered and AgentRuntime.SpentBudget.
