Phase 8 Report

Context compaction can now follow the model's real context window instead of fixed small limits. This makes long workflows practical on large-context models such as Qwen3.8-Flash-Next, which has a 262,144-token window.

What Was Done

  • Added runtime.CompactionPolicy (MaxMessages, MaxChars, KeepMessages) along with DefaultCompactionPolicy and ContextCompactionPolicy(windowTokens, ratio).
  • AgentRuntime.Compaction controls when history moves into durable .aos-memory files. PromptBackend.Compaction controls when history in the prompt gets summarized.
  • agentflow.Engine and StaticBackendFactory pass the policy down to every agent.
  • inference.BackendConfig.ContextWindow is read from AOS_LLM_CONTEXT_WINDOW. aos run --workflow compacts at AOS_COMPACT_RATIO (default 0.8) of that window.

Decisions Made

  • Tokens are estimated at 3 characters per token. That is conservative for the code- and JSON-heavy prompts agents see, so compaction fires before the real usage reaches 80%. At 262,144 × 0.8, the trigger is 629,145 characters of history.
  • Context-window mode has no trigger based on message count, so only size matters. Each compaction keeps the most recent 12 messages live.
  • When no window is configured, the earlier limits still apply: runtime 24 messages / 8,000 chars, prompt 12 messages / 4,000 chars. Existing callers and the TUI behave the same as before.

Known Gaps

  • Tool results such as read_file and run are not truncated. One very large result kept among the recent messages can still go over the window. This was already true before this phase.
  • cmd/aos-tui does not read AOS_LLM_CONTEXT_WINDOW yet.

Tests Run

  • make test and go vet ./...: clean.
  • New tests: the policy budget arithmetic and its triggers; the runtime with a large window versus a tight custom policy; the prompt backend under both settings; parsing AOS_LLM_CONTEXT_WINDOW.
