IPC Step 3: Sender Outcomes

This is step 3 of the slice in ipc-design.md, for gaps B1c and B2c. When a process chain ends with mail no model is known to have read, each message becomes an ipc.dead_letter event, the mailbox empties, and a sender whose chain is live is told in one line.

Result:

  • B1c and B2c now assert, and pass.
  • B1, B2a, B3, B4, B8 and B11 still hold. B4 over 25 trials: 0 lost, 0 duplicated, 0 corrupted, 0 out of order.
  • A chain ending in another OS process reaches the sender, through the kernel's log. That is what the packages guarantee; aos run and aos-tui each hold the state directory's lock, so they take turns.
  • Eval's three ca78ad9 trials (31/31, 8/8, 9/9) and a v0.1.4 record (7/7) replay identically. A run with no mail adds no event and changes no prompt.

What this does not close: a chain nobody closes still produces no outcome. That covers an agent with no restart policy, which is the default, an abandoned child, a run that returned an error or was cancelled, and cause error. Its mail waits, and its sender has only the held on its send result.

Steps 4 and 5 are not built. There were no live runs: everything here used scripted agents.

6. What the Chapter Cannot Claim

  • "Every message ends in something the sender can see." A chain nobody closes does not, and that is the default.
  • "A dead letter means no model read it." not_shown means no checkpoint records it.
  • "A publisher or the operator is told." They get the event.
  • "Shown means acted on." It means a request held the body and the call returned.
  • "The sweep always runs." It needs a run to take a step on that state directory.
  • "Two aos processes exchange mail on one state directory." The packages allow it, and the tests do it, but aos run and aos-tui hold the lock.

7. Known Limits

  • A body split across read_memory pages stays unshown, even if every page was read.
  • A second notice for one chain is possible if a stray message is swept later.
  • In aos-tui, a new root is a new chain, so mail the old root sent bounces to nobody.
  • Nothing prunes bus/dead_letters/.
  • Mail still does not replay identically (decision 11 is Proposed).

8. Should the Engine Close More?

This step did not change it. One case looks worth closing: re-delegating to the same agent after a retryable exit with no restart policy, since nobody in that run will recover the old chain. It would end an operator's Recover of that exit, so it is the user's decision. An abandoned child and an exit left at a run's end should stay open.
