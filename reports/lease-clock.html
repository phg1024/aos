Leases Run on the Kernel Clock, So Runs with Leases Replay

Lease expiries used to come from the wall clock. As a result, a run that acquired a lease never replayed identically. A lease's expiry now comes from the kernel's clock, at the same reading that stamps its lease.* event. A replay reproduces event times, so it reproduces lease expiries.

Result:

  • A scripted run that acquires a lease, writes under it, lets it expire, takes it over and releases it now replays identically.
  • Expiry in live runs is unchanged.
  • All 25 packages, the audit probes and eval's three ca78ad9 replays pass.

2. What "Now" Means for a Lease

  • Acquire (grant, renewal, takeover) decides inside Kernel.RecordEventFunc. It takes one reading of the kernel clock and uses it three ways:
    • to check whether the current lease has expired;
    • to compute the new expires_at;
    • as the event's timestamp.
    The owner-exited check uses the process table from the same kernel transaction.
  • Decisions that record no event read Kernel.Now, which does not advance the clock. These are Get, List, Guard's fence check, Transfer's expiry check, and a refused Acquire.
    • In a live run that is the wall clock, as before.
    • In a replay it is the time of the next recorded event.
    • These decisions turn on time only when another process holds the lease, which needs two agents. Replay does not cover that.
  • Live runs. Expiry is judged exactly as before. The only difference is that an acquire's reading is also its event's timestamp.
  • Several processes on one state directory. Each process reads its own wall clock, and the lease file's lock orders the decisions. Clock skew between hosts is not handled; AOS assumes one host.

3. Old Records

  • run.started now records lease_clock: kernel.
  • A record without lease_clock that granted a lease is refused as not replayable (exit 2). The refusal names the first grant: it granted a lease (lease.acquired a.txt at evt-…) before lease expiries were taken from the kernel clock; their wall-clock expires_at cannot be reproduced. Comparing by meaning would not help: the acquire_lease result showed that expiry to the model, so the requests cannot match either.
  • A record without lease_clock that granted no lease replays as before. Eval's three ca78ad9 trials are identical (31/31, 8/8, 9/9 calls), and legacy_run_started, legacy_tool_intents and legacy_leases still apply.

5. Behavior That Changed

  • A lease event's timestamp and the expiry it records come from one reading of the clock. Before, they were two readings microseconds apart.
  • run.started has lease_clock.
  • Old records that granted leases are refused by aos replay (exit 2), not reported as a divergence (exit 1).
  • New APIs: Kernel.Now, Kernel.SetClocks, Kernel.RecordEventFunc. Kernel.SetClock keeps its behavior.
