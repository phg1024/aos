IPC Design for Chapter 8

This is a proposal, written after the IPC audit (ipc-audit.html, 8a75465). The full text is ipc-design.md at the repo root. Nothing in it is built. Its commit changes no production code.

Revised 2026-11-03 after the book session's review of 951c787:

  • a twelfth decision (rollback re-delivers acked mail), with a new probe B11 that shows the defect;
  • "shown" defined under compaction;
  • exact line-break and control-character rules;
  • tool output weighed as an unframed channel;
  • the operator's grounds tied to the protected state directory;
  • runtime notices exempt from the bounds, and room reserved for replies;
  • the slice reordered to 1, 2, 3, 5, 4;
  • Erlang's mailbox wording corrected.

The chapter's question: when should supervised processes use mailboxes, events, or artifact handles?

The answer, as rules the runtime enforces:

  • Mail carries control and short data: questions, replies, notices, pointers. Bodies are capped at 16 KiB.
  • Artifact handles carry anything over the cap, and anything that is a claim someone should check.
  • The event log holds state changes. Only the runtime writes it.

3. The Contract Decisions

#QuestionDecisionWhy, in one line
1Consumed vs delivered (B1c)Consumed means a model request included its body (MailboxShown). An index entry or pointer does not count. When compaction archives an unshown message, the runtime adds an archived unread notice. The ack still follows the checkpoint. Mail never shown when the chain ends becomes a dead letter with reason not_shown.A successor after a spent budget would never make the call either, so waiting is just slower silence.
2Sender outcomes (B2c, B1c, B7)When the chain ends: an ipc.dead_letter event for each message, and one runtime notice to the sender's chain. A new Kernel.Close marks a retryable exit as final.Erlang sends silently and gives outcomes through monitors. AOS refuses a send to an ended chain at once, and reports per message, because the agent cares about its question. Bounces and other runtime notices are session notes read from the kernel log, not mail.
3Addressing across recovery (B2b)A PID names its chain. A send follows superseded_by (ipc.forwarded). Mail for an open, retryably exited end is held. A send is refused only when the chain has ended.Temporal's Workflow ID vs Run ID. The PIDs that agents know go stale on every restart.
4Subscriptions (B8c)A subscription is owned by the chain and dropped when the chain ends, not at exit. ipc.subscribed and ipc.unsubscribed are events. A late subscriber gets nothing earlier.A topic is a notification, not a store. Anything a late joiner needs is an event or an artifact.
5Trust boundary (B5)A runtime header line, then every body line prefixed | .
  • Line breaks are normalized first: \r\n, \r, \v, \f, U+001C–U+001E, U+0085, U+2028 and U+2029 (Python's splitlines set).
  • Other control characters and bidi controls are escaped.
  • Reserved runtime prefixes are escaped in tool output.
  • Bus.Send refuses the sender user, and only SendAsOperator (aos-tui) can use it. This rests on the protected state directory, which unconfined_run bypasses.
  • A message never widens the receiver's authority.
Framing reduces injection but does not stop it (Spotlighting). The boundary is the capability set (CaMeL's approach), which no message can change.
6Request and response (B7)Messages gain correlation_id, reply_to and deadline. await_reply returns a reply, timeout, recipient_ended or no_reply. The default timeout is 5 min, within the time budget. An await on the asker's own parked child is refused because it would deadlock. Room for a reply is reserved, with at most 16 open requests. A late reply is refused with ErrRequestClosed.gen_server:call and Temporal Update have the same shape. Erlang's 5 s default suits an in-memory server, not a model.
7Size and handles (B6)A 16 KiB inline cap. message_agent can attach artifacts, and read_artifact reads them in 64 KiB pages. A process can read its own chain's artifacts, attached ones and its descendants' published ones. list_artifacts is gated the same way.A message is a turn read in full. A sub-agent's summary is a claim, which the Chapter 11 verdict never trusts.
8Backpressure (B8a)A mailbox holds at most 256 messages or 1 MiB. A send beyond that is refused with ErrMailboxFull. A publish skips full subscribers and reports them. Runtime notices and reserved replies are exempt.Blocking risks deadlock, and dropping breaks at-least-once. Erlang's manuals give no bound. Its max_heap_size kills the receiver at GC, which is not backpressure. Akka's bound is opt-in.
9Addressing policy (B10a)A MessageTargets capability, attenuated. It defaults to the delegation edges (the parent and allowed_agents). A received request grants one reply.The same attenuation as Chapter 4. It also covers runs with no workflow.
10Bus durability (B10c)One bus.json, written in one atomic replace.One transaction already. The caps bound each send's whole-file rewrite at tens of milliseconds.
11Replay (B9)Replay feeds the recorded mailbox_message artifacts back at their recorded step. Multi-agent replay is out of scope.The record already holds the mail and the step it arrived at.
12Rollback (B11)Re-deliver mail the target checkpoint never held, from mailbox_message, with the original IDs. Each is recorded as ipc.redelivered with cause rollback. Subscriptions are kept, and the successor is told which it holds.Mail is outside input; a rollback repeats the process's steps, not its inputs. Dead-lettering would push the loss onto a sender that believes it delivered.

Why this order:

  • The three defects come first (B5, B8c, B11).
  • B2b and B11 go with B8c. All three apply one rule: mail and subscriptions belong to the process chain.
  • Outcomes come next. Every message then ends in something the sender can see.
  • Bounds and handles come before request and response, because they answer the chapter's question directly.
  • Request and response comes last. It has no user inside a workflow: the engine runs one agent at a time, and delegate already is the call to a child. So it can be cut.

5. Hazards

  • Forwarding races Recover: both run under the bus lock, with the kernel read inside it.
  • Mail on open chains: it is held until the chain is closed. The engine must close every exit it declines to restart.
  • Bounce storms: one notice per ended chain per sender, and a bounce is never bounced.
  • Framing changes prompts: it is recorded as peer_framing, and older records replay with the legacy rendering.
  • The cap breaks large sends that work today: the refusal names the remedy.
  • Deadlocks: only the asker's own parked child is detected. A cycle between separate processes ends by timeout.
  • Handles cannot be revoked: sending a handle is like sending the bytes.
  • The shared filesystem is an unframed channel between agents. Step 1 escapes the runtime's reserved prefixes in tool output, but text in a shared file can still persuade. Only capabilities bound what follows.
  • Rollback repeats outgoing mail: the repeated steps may send again under new IDs.

6. Prior Art Cited (URLs in the doc)

  • Erlang:
    • sending to a pid "never fails, even if the pid identifies a non-existing process";
    • monitors send 'DOWN', with reason noproc for a process that does not exist;
    • gen_server:call/2 has a 5000 ms default;
    • the manuals give no bound on the message queue; max_heap_size is checked at GC, counts the queue only when it is on_heap, and kills the process (default kill: true).
  • Temporal:
    • a Workflow ID versus a Run ID;
    • SignalWorkflow with an empty run ID picks the running execution;
    • an Update returns a result or a failure, and is deduplicated by Update ID per run.
  • Akka:
    • the default mailbox is unbounded;
    • bounded mailboxes are opt-in, and messages that arrive when one is full go to dead letters.
  • Spotlighting (Hines et al. 2024) and CaMeL (Debenedetti et al. 2025).
  • Python's str.splitlines, for the line-boundary set, checked in Python 3.
