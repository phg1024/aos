Supervision Steps 1 and 2: Exclusive Recover and Tool Intents

These are steps 1 and 2 of the slice in supervision-design.md (d80ed15), built for Chapter 7. Steps 3 (fencing) and 4 (a restart policy) are still proposed.

  1. Exclusive Recover (N1, N2). An exited process is recovered at most once. Recovery starts from the checkpoint the exit names, and any other checkpoint is an explicit, recorded rollback.
  2. Intents (N6). A world tool records tool.started before it acts, and its outcome names that intent. A call cut off while the run is alive records its file changes. A call whose process died is reported to the next runner and in aos inspect.

Result:

  • go vet ./..., go test ./... and the audit probes all pass.
  • 20 concurrent Recovers now make 1 successor; before, they made 20.
  • Eval's three ca78ad9 trials replay identically.

1. Exclusive Recover

  • Kernel.Supersede(pid, spec, data): one transaction under the kernel's file lock. It does three things:
    • refuses a process that has not exited (ErrInvalidTransition), or one that already has a successor (ErrSuperseded);
    • spawns the successor (process.spawned);
    • appends process.superseded on the old process and sets its superseded_by. The event carries successor, checkpoint and, for a rollback, rollback_from.
    A table that missed the event is repaired from the log, as with the other process.* events.
  • runtime.Recover:
    • An empty checkpoint means the one the exit names.
    • Any other checkpoint needs RunOptions.Rollback; without it, the call is refused before anything is spawned.
    • A superseded process gives ErrNotRecoverable wrapping kernel.ErrSuperseded, and the error names the successor to recover instead.
  • The TUI's /recover uses the same path.
  • aos inspect shows superseded by pid-….

2. Tool Intents

  • Intents: run, write_file and edit_file (runtime.WorldTool) record a tool.started kernel event after the capability check and before they act. The event holds the tool, the command or path (clipped to 200 bytes) and args_sha256. If the event cannot be written, the tool does not run and the run fails retryably.
  • Outcomes carry intent metadata:
    What happenedOutcome
    The tool returnedtool_result
    A tool error, including one that ends the runtool_error
    A timed-out commandtool_error, with the files it changed
    A cancel, strict budget or SIGTERM during the calltool_cancelled, with the changes. The agent's note adds started=true may_have_taken_effect=true changes="…".
    The process died during the callNone at first. The next Resume or Recover records tool_interrupted, produced by the process that runs next, and tells the agent before its next step.
  • aos inspect lists every call that started and did not finish: open, cancelled, or interrupted with who was told.
  • Limit: the intent and the note make a repeat visible; they do not prevent one. A model can repeat the call anyway. A7's scripted model does, and its file gets a second line.

3. Old Records

  • process.superseded never appears in a replay, because replay does not recover.
  • A record with no tool.started event predates intents. It is replayed with NoToolIntents, which records no intents, no intent metadata, no tool_cancelled and the old cancel note. The report sets legacy_tool_intents, and the CLI prints the record predates tool.started intents; replayed without them.
  • A record with intents is replayed with them and compared byte for byte. Changing one intent's type in such a record makes the replay diverge at that kernel event.
  • Tool error payloads keep their old JSON when nothing changed. The changes key is added only for a cut-off command.

6. Behavior That Changed for Existing Runs

  • A Recover with a checkpoint other than the exit's fails unless Rollback is set. Recover(pid, "") now works.
  • Every run, write_file and edit_file call adds one tool.started kernel event, so event counts grow.
  • The outcome artifacts of those tools gain intent metadata.
  • The cancel note for a world tool is longer. This only matters after a cancel.
  • A tool error that ends a run (without ContinueOnToolError) now leaves a tool_error artifact.
  • tool_cancelled and tool_interrupted are reserved artifact types.
  • Resume and Recover read the event log and the artifact index once, to find open intents.
