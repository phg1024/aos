IPC Audit at v0.1.4 (180d076)

This audit measures AOS mail as it stands, for Chapter 8 (IPC Without Shared Context). It covers the mailbox bus (internal/ipc), the send, publish and subscribe actions and tools, and replay.

  • Probes B1 to B11 are in bench/ipc/audit_test.go, behind the ipcaudit build tag.
  • They use scripted agents only: no live model and no phg-gpu.
  • No production code was changed.
  • The design that answers these findings is ipc-design.html (ipc-design.md).
  • A probe passes whatever it observes, and logs the behavior as FINDING: lines. A comment on each probe names the contract it was measured against.

Summary:

  • Holds:
    • at-least-once delivery, with deduplication by message ID across SIGKILL, Recover and a lost ack;
    • per-sender FIFO across two Recovers;
    • no loss, duplication or corruption across OS processes: 0 of 5,000 messages over 25 trials.
  • Three defects:
    • a topic subscription does not survive Recover;
    • a numbered sender label in a message body is not quoted, so it can pass for a separate message.
    • added 2026-11-03 (B11): a rollback loses mail that was acked after its target checkpoint, with no record of the loss.
  • Gaps: no size bound, no backpressure, no correlation ID or timeout, silent drops of stranded mail, any-to-any messaging, and no replay of mail that came from outside the run.

How to Re-Run

go test -tags ipcaudit -count=1 -v ./bench/ipc/                          # all probes, about 95 s
go test -tags ipcaudit -count=1 -v -run 'B5' ./bench/ipc/                 # one probe
AOS_IPC_TRIALS=20 go test -tags ipcaudit -count=1 -v -run B4 ./bench/ipc/ # more concurrency trials
go test -tags ipcaudit -count=1 -v ./bench/ipc/ 2>&1 | grep FINDING          # findings only

Run the probes by package. go test ./... does not run them without the tag, and it rewrites reports/least-privilege-probes/results.

B6 Size Bodies of 1 MB and 10 MB, sent by the send action and by message_agent.
  • Accepted: both sizes, with no cap.
  • Receiver: a lone 1 MB message is inline in the first request, as a 1,048,623 byte entry. When another message follows it, the default compaction moves the bodies into a memory segment before the call (2 MB and 20 MB segments).
  • Sender: its own action turn holds the body, so its checkpoint is 21 MB for 10 MB. The message_agent result echoes the body, capped at 69 KB.
  • Disk: mailboxes.json reaches 20 MB and is rewritten on every send. A small send takes 20 ms on an empty bus and 140 ms behind 20 MB. The event log stores IDs only.
  • Budgets: no byte check; tokens are counted after the call.
  • Artifact handle: publish_artifact makes one, but no tool reads its body. read_memory refuses anything that is not the reader's own memory_segment. list_artifacts lists every process's artifacts, ungated.
 None for mail. Tool output is capped at 64 KiB.gap
B7 Request and response A parent mails a parked child and calls await_agent. The child then exits without answering. await_agent is a non-blocking poll: it returned state:ready at once, then exited code:0. The question stays pending for the exited child. ipc.Message has no correlation ID, reply-to or deadline. None for mail. The engine's wait is the only request and response: a child parks with a question, and the delegator answers by delegating again (DelegateHandler, engine.go:585).gap

  • Replay opens a fresh, empty bus (replay.go:284). It does not feed back the recorded mailbox_message artifacts, and it detects the gap rather than hiding it.

Notes for the Chapter

  • Delivery is at least once, made exactly once by the receiver: the bus redelivers until an ack, and the session drops repeats by ID. Acks follow checkpoints, and the first step after a resume asks for redelivery (runtime.go:798).
  • The bus is a set of durable files under a lock, not a queue service: every operation rewrites mailboxes.json whole. That is why it holds across OS processes, and why its cost grows with the backlog and with body size.
  • On the model's side there is no role boundary for mail: mail, tool results and user input are all user turns, told apart only by their text prefix, and the system prompt asks the model to treat message from … as information.
  • What is missing for request and response: a correlation ID, a blocking receive with a deadline, and a bounce when the replier exits.
