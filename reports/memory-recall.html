Memory Recall Aids: Agent-Written Archive Index, Write Feedback, Handoff Re-notice

In the phase-3 live run, the archive was effectively write-only: 1 search_memory call and 0 read_memory calls in the whole run. In the own-memory probes, facts that were in neither the live context nor working memory scored 0/18 in both arms. The header listed each archived segment only as tool counts and paths ("run x45"), so the agent could not know what was there to look for. This phase gives the agent a way to write its own map of each segment at handoff (A1). It also adds three aids for how working memory is written (W1–W3) and one for an ignored handoff (W4), and fixes model-call failures that used up steps.

Result: 33 new tests pass, and go test -buildvcs=false ./... passes. Every aid can be turned off on its own, and all of them are on by default. With every aid off, the prompts are byte for byte what they were at ccb6e8b, checked against golden files. The effect of A1 and W2 is unmeasured until the eval session runs its probes. Unit tests show the mechanisms work. They cannot show that agents use them well.

Backend retry
  • A failed model call is retried within its step: 12 attempts, waiting 1s and doubling up to 2 minutes, about 12 minutes in all. Each retry is a backend.retry kernel event, and retries take no steps.
  • When the retries run out, the process exits retryable with a checkpoint, as a budget exhaustion does, to be recovered once the endpoint is back.
  • This replaces the old behaviour: each failure took a step, with try_different_strategy=true. That behaviour cost verifier pid-000020 146 of its 160 steps.

Configuration

  • One options struct. runtime.RecallPolicy holds four negatively named fields, so the zero value turns everything on. runtime.RecallOff() returns the all-off policy.
    • The runtime reads it from AgentRuntime.Recall.
    • The prompt reads it from PromptBackend.Recall. Set both to the same policy.
  • Per workflow. The workflow JSON can set it as "recall": {"no_agent_index": true}. Engine and StaticBackendFactory pass it to every agent's runtime and prompt.
  • Default policy unchanged. CompactionPolicy is unchanged, so the whole-struct comparison in compactionPolicy() is unaffected.
  • Notices in the trace. Each notice an aid emits is recorded as a memory.notice kernel event with item set to w1, w4 or a1 (a1: a handoff that asked for an index). memory.compacted also records handoff_steps, handoff_renoticed and agent_index_lines.
  • Header size. A backend that implements runtime.HeaderSizer (PromptBackend does) gets a memory.header event with the byte sizes of the working-memory snapshot, the archive index and the agent index, and the number of segments that show theirs. The event is written at a run's first call and whenever the sizes change. The header is fixed between compactions, so this covers every call without logging each one. It is gated by A1.
  • memprobe flags. These are wired by the eval session, at its request: the harness should not be written by the implementer of the change it measures. Nothing in internal/memprobe changed. Note: memprobe builds PromptBackend and AgentRuntime with zero Recall, so on this commit its probes run with every aid on. Frozen arms must set runtime.RecallOff() on both to stay comparable.

Handoff on an existing checkpoint

RunOptions.HandoffOnly runs only a handoff:

  • The first step gives the notice for what the compaction policy would archive.
  • The agent takes its handoff steps.
  • The run parks ready as soon as the history is compacted, before any other action runs.
  • A history with nothing to archive is refused with ErrNothingToArchive.

Use it the way memprobe asks a probe question:

  • Work in a copy of the state.
  • Spawn a process with resumed_from set to the checkpoint's owner and no tool grants, so only the memory tools can run.
  • Resume it from the checkpoint.

The input checkpoint is only read; a test checks that it is unchanged. The checkpoints a phase-3 compaction was cut from are the ParentIDs of each memory_segment. Read the result with runtime.SegmentIndex(store, segmentID), which returns []IndexLine{From, To, Text}, or from the agent_index field of the segment's JSON. The runtime does not know the model, endpoint or sampling settings. The caller, which builds the completer, records them.

Bounds

  • Per segment, the rendered index may be at most 1,536 bytes (MaxSegmentIndexBytes). A larger index is refused, never truncated.
  • In the header, the agent indexes together may be at most 6 KB (MaxAgentIndexBytes). The newest segments come first. An older segment over the cap shows only read_memory artifact_id=… shows it.
  • A handoff may take at most 4 steps before compaction. After the first step, the agent gets another step only while it is writing memory (with A1) or is due its single reminder (W4), and only while the live history is within 16 KB of the trigger.
  • A later handoff step whose action is not a memory write is compacted before its action runs, so its output lands on the compacted history. Without these limits, the output of the first handoff step would be shown to the model. Compaction used to archive that output before any model call saw it.

Verification

  • Old behaviour. With every aid off, the system prompt, the task header and the single-prompt user prompt equal golden files written by the same test at ccb6e8b (TestRecallOffKeepsThePromptsAsBefore). The existing handoff and hysteresis tests now run with RecallOff() and pass unchanged. So do the crash-recovery tests, with retries off.
  • New tests: backend retries; evidence forms; overwrite feedback (on and off); reminder once, never twice, and not when off or when working memory exists; index storage, immutability across a second handoff, refs and read_memory; index refusals (no handoff, over cap, malformed, aid off); the overrun bound; HandoffOnly; independent switches; prompt wording on and off; header rendering with the cap fallback; and a workflow spec's policy reaching both prompt and runtime.
  • Mutation check. 16 mutants of the new mechanisms. 15 are killed. The first sweep had two survivors; a test added for the reminder guard kills one. The survivor: dropping the line that makes a crash-replayed compaction keep its adopted segment's index. That is equivalent in every tested path, because the replay rebuilds the same pending index from the checkpoint.

Changed From the Contract

  • R1 (repeat detection) and R2 (archive hits on writes) were dropped, as the book session asked. V1's offline replay was dropped with them: A1 needs a model, so eval measures it with HandoffOnly.
  • W4 also repeats the notice when, with A1 on, the agent wrote no index. With A1 on, a handoff may last up to 4 steps while the agent keeps writing memory. Both stay within the bounds above.
  • The header size is logged when it changes, not on every call. It changes only at compaction.
  • The backend fix, and W1's section_keys and W2's delete guidance, come from the eval findings the user approved in this session.

Not Yet Known

  • Whether agents write useful indexes. The own-memory evaluation's key metric is facts that were not recorded, which scored 0/18 in both arms. Whether A1 moves it is unmeasured.
  • Whether the reminder and the pointer wording change behaviour on the live model.
