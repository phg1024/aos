Phase 15 Report: No Process Left Running

Design-review item 7. Every run now ends in a recorded exit or a checkpointed park. Recovery is refused unless the process is exited and retryable. Leases are safe across processes, end when their owner exits, and move to a recovered process. A run that dies leaves orphans that aos reap turns into recoverable exits.

What Was Done

  • One closer. runSession runs the agent loop (runSteps) and then closeRun. If the process is still running, whatever path returned, the closer exits it as {1, error} with no origin, naming the latest checkpoint (or the one the run resumed from). Infrastructure errors (storage, bus, backend) are retryable. Contract violations are not: a tampered, foreign or reserved artifact, an unknown parent or producer, malformed output, or an invalid transition. Exits and parks the loop records itself pass through unchanged. This replaces patching the roughly 20 bare return RunResult{}, err sites.
  • Exit records name their checkpoint. kernel.ExitStatus gains checkpoint, which goes into the process.exited event and is replayed. The runtime sets it on agent exits (overwriting any value from the model), step limits, refusals, failures and the closer's exits.
  • Exited PIDs are refused. runSession returns ErrProcessExited before any model call, tool or artifact.
  • Guarded recovery. Recover returns ErrNotRecoverable unless the process has exited with a retryable status, from either origin. Resume of an exited process goes through the same check, and the item-5 ownership check still applies. The recovered process takes over the old one's unexpired leases. If that transfer fails, the new process is exited retryable rather than left ready.
  • Leases (internal/lease, rewritten).
    • The lease file is read and written under internal/filelock and replaced atomically through a synced temp file.
    • New(root, kernel): with a kernel, a lease whose owner has exited is free on acquire, get and list.
    • The same owner renews (TTL extended, token kept).
    • Each new grant, takeover or transfer gets a fencing token, strictly increasing per resource. The last token per resource is kept after release, so no token is reused.
    • Transfer(from, to) is new, and so is List().
    • lease.acquired, lease.renewed, lease.released, lease.taken_over (reason expired or owner_exited) and lease.transferred are kernel events, each written before the lease file changes.
    • Unversioned lease files from before this change are still read.
  • Workflow root lifecycle. Engine.Run moves the root to running as soon as it spawns it. A crashed workflow's root now reads as orphaned, not unstarted. The TUI has no separate root: its interactive agent is the top process and already runs through runSession.
  • internal/statedir (new): Lock (moved from cmd/aos), InUse, LatestCheckpoints, and Reap. aos-tui now takes the state-directory lock as well, so reap can never close a live session's processes.
  • aos reap <state-dir>: if no run holds the lock, it exits every process that has no exit record with {1, "orphaned: owning run is gone", retryable}, naming its latest checkpoint. It refuses where flock is unavailable (filelock.Supported).
  • aos inspect accepts flags after the path. It says whether a run holds the directory, or how many processes are orphaned (with a pointer to aos reap), and lists live leases with owner and token.
  • TUI. After a turn, the TUI follows result.PID, so resuming an exited process continues as the recovered PID. Because results now carry the latest checkpoint even on errors, the TUI no longer loses its place after a failure.

The root now reads running rather than ready. Each reaped exit is retryable and names its latest checkpoint, and the test then recovers the coordinator from it.

Decisions and Divergences

  • The closer acts only on a process left running. A process that stayed ready because its first transition failed never ran, so it is left alone. The loop's own exits keep their existing retryable flags: backend errors and the step limit are retryable; tool errors, refusals and malformed output are not.
  • Agent-origin retryable exits are recoverable, as you suggested. Resume already gated on Retryable alone.
  • The checkpoint is a new ExitStatus.Checkpoint field in the kernel record, not part of the reason.
  • A lease of a PID the kernel does not know is freed only by expiry, not treated as dead.
  • Leases are not deleted when their owner exits. They read as free, which leaves them for Transfer after a Recover.
  • The engine still exits a cancelled child as {130, cancelled} (its own policy). For other errors, its item-1 exit is now a no-op, because the closer has already recorded the exit.

Limits

  • If the kernel cannot be written, no exit can be recorded at the time. aos reap is the recovery path once the run is gone.
  • Fencing tokens are issued but not yet checked at write sites.
  • On non-unix platforms, file locks do not coordinate processes, so leases are exclusive only within one process, and reap refuses.
  • A lease event is written before the lease file. A crash between the two leaves an event for a grant that did not happen; the file stays authoritative.
