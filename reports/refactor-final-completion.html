Key Decisions

  • Agent meaning now lives in workflow specs, not in AOS core.
  • Verification and review are optional behaviors chosen by workflows.
  • Text UI interaction uses the same runtime and mailbox substrate as workflow execution instead of a separate chat-only stack.
  • Tool-semantic shortcuts are acceptable when they arise from generic tool behavior rather than hardcoded role names; this is how successful single-purpose writers now auto-exit cleanly.

Issues Encountered

  • Strict control JSON from fully live coordinator agents was initially brittle enough to require repair and stronger action examples.
  • Writer loops after successful tool execution had to be constrained explicitly.
  • The runtime did not originally support yield/block/resume behavior that a real interactive terminal session needs.

How They Were Resolved

  • Added raw-response parsing plus an automatic repair pass in the prompt backend, which let the all-live workflow path complete cleanly.
  • Added a generic writer auto-exit shortcut after a successful write_file.
  • Added resumable checkpoints, recovery support, and mailbox-backed blocked/yielded session flow to the runtime.
