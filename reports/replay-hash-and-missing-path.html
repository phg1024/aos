Replay Verifies Payload Hashes; a Missing Path Is an Argument Error

These are two small fixes on main after v0.1.2 (bd4a47c). The book session found both in eval's killed cobol trial.

  1. aos replay now checks every recorded payload against the index's sha256 before it replays anything.
  2. write_file, read_file and edit_file called without a path now return <tool> requires path. This is a tool error, with no capability.denied event.

Result: go vet ./... and go test ./... are clean, and each new test fails on the old code.

1. Replay Checks the Record First

  • Before: record.payload read artifacts/payloads/<id>.json with no hash check. A payload changed on disk was replayed as if it had been recorded that way. It surfaced as a request divergence at the first call it fed, and nothing said the record had been changed.
  • Now: load checks every index entry that has a sha256 against its payload file, in ID order, before anything else runs. The store applies the same rule on each read.
    • A mismatch is ErrNotReplayable wrapping artifact.ErrArtifactTampered. It names the artifact, its type and both hashes, and the CLI exits 2.
    • A missing payload file is also not replayable.
    • Entries with no hash predate hashing and are trusted, as the store trusts them.

2. A Missing Path Is Not a Denial

  • Cause: the file tools ran filepath.Clean(args["path"]) first, and Clean("") is ".". The process's working directory lies outside its grants, so the call was refused with path outside the granted scopes or mounts and logged as capability.denied. That is what happened at evt-000007 and evt-000008 in the cobol trial. edit_file already had an if path == "" check, but it ran after Clean, so it never fired.
  • Now: requiredPath runs before any capability check. A missing or blank path returns <tool> requires path, the same kind of error as write_file requires content.
  • Tools checked:
    • write_file, read_file, edit_file: fixed.
    • list_dir, find_files: unchanged. An empty path or root means the first mount's root, by design.
    • run, web_search, web_fetch: no path argument.

Replay of old records

Old records with these denials still replay the same. Replay does not run the tools; it returns the recorded outcome, and the recorded error rebuilds ErrPathDenied, so the runtime logs the same event. Replaying the untouched cobol record with this build produced these results:

  • All 31 calls matched.
  • evt-000007 and evt-000008 came out identical.
  • evt-000003 (run.started) differs. That comes from d9b3514, which records settings as they take effect: it adds budget_time, *_source and max_steps_*, and fills in the default values. It does not come from this change. So records made before d9b3514, including eval's three ca78ad9 trials, no longer replay as identical on v0.1.2.
