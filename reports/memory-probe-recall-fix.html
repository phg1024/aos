Memory Evaluation: Agent-Written Archive Index (A1), Follow-Up on the Handoff Fix

The first A1 evaluation (memory-probe-recall.html) stopped after its handoff phase: 5 of 27 handoffs left an index. aos code changed the handoff in 50a7cfe. This follow-up re-ran the same frozen plan on that runtime: the same 9 segments, 3 draws each, the same 11 probes, arms, rubric and stop rule.

The handoff now leaves an index: 26 of 27 (was 5), the stop rule passed, and all 198 probe answers ran.

Primary result, not significant: on the two unrecorded probes the plan names as primary, A1 gave the main fact in 5 of 18 answers against 1 of 18 for C (two-sided Fisher p = 0.18).

  • r5-register-counts: 4/9 vs 0/9. All four right answers came from the index line (no memory read). The three answers from draw 2, which kept no index for that segment, were all wrong.
  • r2-verify-dir: 1/9 vs 1/9, but this half did not test the index. Every draw indexed the truth (#37, "unreadable, Operation not permitted"), yet the header shows agent indexes newest first within 6 KB, and the four round-2 indexes total about 8 KB. The oldest, which holds this truth, was replaced by a pointer in all three draws.

Secondary: r8-sibling-pairs exact 9/9 vs 7/9. A1 took the number from the index with no read; C needed a search and a read (2.7 model calls and 98K tokens per answer, against 1.0 and 42K).

Harm check: 28 A1 answers stated a fact found only in an index line, without reading what it cites. 27 of them gave the main fact right. None repeated an error from an index line; one misread a correct line.

One possible regression, not established: r5-tir-guard main 6/9 in A1 against 9/9 in C (Fisher p = 0.21). Three A1 answers say the guard never fires, restating the wrong working-memory entry, which no C answer did outright.

Cost:

  • Answers: A1 used fewer tokens overall (42.5K vs 46.1K per answer), because unrecorded probes no longer search. Recorded probes cost about 3.9K more tokens per answer, roughly the 4.3 KB of index in the header.
  • Handoffs: about 198K tokens each (154K in the first run).

    • Four answers (A1 2, 3, 8, 9) gave 1024 with no read. A1 2 places it "earlier in this phase" rather than this round, so it is main but not exact.
    • A1 1 cites the line but calls 1024 a device cap and says no occupancy figure was obtained (contra). A1 7, draw 3, ignored its lines.
    • Draw 2 (A1 4 to 6) had no index for the segment and gave the same wrong answer as every C answer: no occupancy figure this round.
  • r2-verify-dir (truth #37: the verification directory is not readable).

  • r8-sibling-pairs.

Regression Check

  • r5-tir-guard: main 6/9 in A1 against 9/9 in C.
    • A1 1, 5 and 9 say the reflectance-1 branch never fires, restating the wrong working-memory entry. The archive (#14, #63) shows it fires for rays entering the glass, because eta = ior_t / ior_i.
    • Draws 2 and 3 have an index line for #14. Draw 2's reads "pt_fresnel (TIR guard (ior_t/ior_i)^2, must not correct)", and A1 5 argues from (ior_t/ior_i)^2 to the wrong conclusion. That is suggestive, not shown.
    • On the other side: exact was 2 vs 1. A1 4 read #13 to #15 with no search, guided by the index, and corrected its entry.
    • Fisher p for main is 0.21. With 9 answers per arm this is not a measured regression, but it should be watched in a live run.
  • r5-empty-base: exact 5/9 vs 0/9. All 9 C answers, and A1 1 and 4 to 6, say the shaders were missing (contra). The A1 answers that got the mechanism right (round-3 header, so the round-4 shaders failed to compile) took it from the index line at #68, with no read. Three of those five add a wrong side detail; a stricter reading would leave exact at 2/9.
  • r2-root-exit: exact 8/9 vs 6/9. All 9 A1 answers quote 107.004 / 125.973 from the index line at #143 or #135 to #143; C quotes 107.0 / 126.0 from working memory. The contra answers misstate the no-clamp baseline (the archive: 101.150 / 116.465 at #133).

Index Quality

338 lines were kept across 26 indexes. By plan, 40 were drawn with random.Random(20261030), plus every line citing a truth message of an unrecorded probe (6; one overlaps): 45 lines in all. Each was read against the messages it cites (index_lines.py, index_lines.md; grades in index_grades.json):

  • 37 hold, 8 partly, 0 wrong.
  • 4 of the 8 partly cite the tool result of an edit or write whose detail is in the agent's call one message earlier (for example "75: rewrote pt_integrator.metal (constant params, per-thread atomic sample count)"; the detail is in #74).
  • 2 cite #31 for facts that are at #33: "missing Metal Toolchain" and 1024. #31 only shows xcrun finding a metal path.
  • 2 have a detail not in the cited message ("builder that gave 105ms"; a "-0.19%" not in #9).
  • Every line that cites a truth message holds, apart from the #31 lines just noted. The three #30 sibling-pairs lines, outside the plan's set, hold.
  • Size: 1 to 30 lines and about 0.9 to 2.6 KB per index, against per-segment caps of 1536 to 4096 bytes. No line was dropped by the plan's range rule: every archive lay inside its original segment.
  • Coverage: lines cite 1 to 71 of a segment's messages, typically about half (index_lines.py prints each).

For aos code

  • The fix works on all four points it targeted: the index is asked for first, the archive equals the notice range, rejected lines no longer discard the index, and refusals get a retry.
  • The header cap now decides what is seen. With 4 indexed segments the oldest segment's index was replaced by a pointer, and that segment held the fact the probe asked for. Showing newest first favours recent segments. The oldest segments, which working memory has had the longest to drop, lose their index first.
  • Run-on indexes: 2 of 26 were written on one line and kept as one line. A parser that splits "N: ... M: ..." within a line, or a rejection of over-long lines, would catch it.

Caveats

  • Re-run handoffs, not live ones. The handoff process had only the memory tools, and earlier segments had no index. In the probes the index sits on the checkpoint's segment references, so a read_memory of a segment does not show it.
  • Small samples. 9 answers per probe per arm, from 3 draws of one model on one live run.
  • Grading: by hand and not blind; A1 answers can show they used the index. This session graded the three unrecorded probes. Two reader agents, briefed with the rubric, the earlier grades and the archive, graded the other eight; two of their claims were spot-checked against the archive and held. Their uncertain calls are listed in grading/grades-a.json and grades-b.json.
  • Direction of the sibling-pairs result: not graded. The log gives a mean in the candidate's favour and p10 and p50 in the base's.
  • Other aids off: w1, w2 and w4 were off in both arms and in the handoffs, as in the plan; this is not a live a1 configuration.
