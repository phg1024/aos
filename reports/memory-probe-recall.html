Memory Evaluation: Agent-Written Archive Index (A1), Handoff Phase

A1 asks the agent, at each handoff, to index the messages about to be archived; the header then shows that index next to the segment. This evaluation was to test whether the index lets the agent recover facts it archived but did not record in working memory, which it never did in the own-memory evaluation (0/18 per arm on the two unrecorded probes).

Result: the probe phase was not run. The handoffs that were to write the indexes produced one in 5 of 27. Neither segment that holds a primary probe's answer got an index in any of its 3 draws. The stop rule (added at aos book's request after 2 handoffs, before the rest were seen) stopped the run before any probe answer. So this report says nothing yet about whether an index helps; it says the handoff, as built in d65b94f, rarely leaves one with this model.

Why no index, 22 handoffs:

  • 8: the index was refused for being over the 1536-byte cap (1566 to 2684 bytes).
  • 7: the index was refused because one line cited messages past the range the notice named. The agent indexed up to where its history then ended.
  • 7: the agent never called index_memory; it spent its handoff steps on working memory or stopped.
None of the 15 refused handoffs got a step to retry: in each, the refused call was the agent's last action before compaction.

Cost: 27 handoffs, 2.6 model calls and about 154,000 tokens each (4.16 million in all), 23.5 minutes on phg-gpu.

Each segment's handoff was re-run with --recall a1 (the other aids off) from the last checkpoint before the live run's own handoff notice for it, 3 draws each: 27 handoffs, 2026-10-30 17:28:32Z to 17:52:03Z. Each ran in a probe process with only the memory tools, in a copy of the run's state.
  • Probes: not run. Arm C had started at 17:52:03Z; the stop rule ended it 2 seconds later, before it wrote any sample.

Why the Handoffs Left No Index

  • Working memory first, then one index attempt. The notice asks for working memory, then the index. In 25 of the 27 handoffs the agent's first action was update_memory (1 to 4 calls in all), and the index came last, if at all.
  • No retry after a refusal. In all 15 refused handoffs the refused index_memory call was the agent's last action. 14 of the 15 ended at 2 or 3 handoff steps, under the runtime's limit of 4, so something other than the step limit ended them. The likely cause is the bound on later handoff steps (they are given only while the history is within 16 KB of the trigger), but this was not verified.
  • The cap is not in the notice. The notice asks for "one line per thing you might need to find again" and gives no size. Refused indexes were 1566 to 2684 bytes against a 1536-byte cap. A refusal discards the whole index, as the runtime's design says (refused, not truncated).
  • The notice's range is shorter than what is archived. In 23 of 27 handoffs, compaction archived messages past the range the notice named (for example notice 30–118, archived 30–120). Lines that cited the extra messages, or messages written during the handoff, were refused, and with them the whole index.
  • Never called. 7 handoffs. In two (art-003059, draws 1 and 2) all 4 steps went to update_memory; in the other five the handoff ended after 1 or 2 steps, with working memory only (three) or no tool call (two).

aos code was told after the first handoff and is changing the notice: the cap and the range in the notice, the index asked for first, and one retry after a size refusal.

The Indexes That Were Kept

Five indexes, 9 to 19 lines, 1097 to 1478 bytes; no line was dropped by the plan's range rule. The round-2 segment art-000507 was indexed in all three draws, and each draw has a line for #93, the probe r2-first-sah's truth: "benchmark regression render_ms_best=4416.3 gpu_ms_best=4413.7" (draw 1). Message #93 holds render_ms_best=4416.317 ... gpu_ms_best=4413.659, so that line holds. This is one spot check, not the planned index-quality grading, which belongs to the probe phase and was not done.

The Stop Rule

After the first 2 handoffs had finished, both without an index, aos book asked that the probe phase not be spent on an A1 arm that would differ little from C, and that the threshold be written down before more handoffs were seen. This session stopped its progress watch and committed the rule in 7068f60, while the handoff phase was still running:

  • The probe phase runs only if at least 14 of the 27 draws kept an index line, and each primary truth segment (art-000414 for r2-verify-dir, art-001661 for r5-register-counts) kept one in at least 2 of its 3 draws.
  • gate.py applies it; gate_watch.sh ran it when the handoff phase wrote its indexes and stopped run.sh on FAIL.

Gate result (17:52:05Z): FAIL: 5 of 27 draws kept an index; art-000414 0 of 3, art-001661 0 of 3.

An Observation Outside the Plan

The plan discards the working memory each handoff writes, so it is not scored. In one of the three re-runs of the first round-2 segment (art-000410, draw 1), that working memory records the fact the probe r2-verify-dir asks for: the verification directory is not readable from the sandbox. The live run's own working memory did not hold it. None of the three re-runs of the round-5 segment (art-001657) recorded the occupancy figure that r5-register-counts asks for.
