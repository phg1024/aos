## pid-000022 (round-7 writer)

### A — pid-000022 #219-#227 — "a different BVH is bit-safe" stated as fact after it had found that tree changes break bit-identity
- Claim: #219 (art-002909): "A different BVH is bit-safe: the closest hit is the same min-t triangle regardless of tree, and duplicates/order cannot change the recorded winner." Repeated at #223: "Tree quality is the biggest remaining lever and is bit-safe (min-t hit is tree-independent)."
- Already available: #58/#60 (art-002825): bins16/bins64 trees "DIFF ... alt-view ... differ: char 1022129". #64: "DIFF leaf2@256 alt-view". #69 note: "leaf2 rejected (alt-view@256spp differs: BVH shape changes tie-breaking order for exact-t ties)". WM v3 (art-002743): "leaf_size 2 ... DIFFERS at 256spp alt-view (#64) -> REJECTED (tie-break order changes). bins 16/64 also differ (#58)". By #219 those messages were archived. The active WM v4 (art-002822) still said "REJECTED with evidence: leaf2 (#64), bins16/64 (#58)", but had lost the tie-break reason.
- Acted on: it built PT_BVH_MAX_DEPTH 20 (#227), tested identity twice (#228, #230 with stack 24), and then "rediscovered" the same mechanism as a "CRITICAL FINDING" (#231). The writer log and the exit report then present that as new. It corrected itself after about 4 steps, but only after it had spent two build+render experiments on the wrong premise. (Round 2's log had also already timed depth 16->20: "61.8ms, no gain".)
- Confidence: high. The contradicting results are its own measurements earlier in the same round, and its WM points to them.

- Confidence: high.

## pid-000025 (round-8 writer)

### B — pid-000025 #39-#53 — E5 "16-byte u16 node" is the round-6 node layout that round 7 had replaced
- Experiment: #39 (art-003133): "NEW HIGH-LEVERAGE IDEA never tried: pack nodes to 16 bytes with the SAME quantized integers stored as u16 ... Round 7's -0.44% was the convert cost at unchanged size". Built, identity-checked and A/B'd (#53: 0/16, +0.90%).

Writer log line 245 (read at #9): nodes "were stored ... with quantised bounds and decoded with u2f on every load". - Confidence: medium. The answer was available, and the stated reason is false given the delegation, but the shared log misled it.
