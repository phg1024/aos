Least-Privilege Probes (Chapter 4), AOS 283a92e on macOS

Four probes asked by aos book, run with a scripted backend through the real AgentRuntime, no model. Each attempt is recorded as what was tried, the exact tool message the agent saw, the disk change, and whether a tool_error or tool_result artifact and a capability.denied kernel event exist.

One real hole: the file tools' protection is case-sensitive on a case-insensitive volume. protected() (internal/tools/runtime.go) and the read-only-mount check in withinAllowed (internal/capability/policy.go) compare paths lexically after EvalSymlinks, which keeps the caller's spelling. On this Mac's APFS volume <ws>/.AOS-STATE opens <ws>/.aos-state, so:

  • write_file and read_file reach the protected state directory through a case variant: new files, the kernel's events.json and processes.json read back, and both kernel records rewritten: after a case-variant write_file, the kernel reports a forged event (evt-999999) and the artifact store lists a forged artifact (art-999999; its next ID became art-1000000). Every one is an ordinary tool_result with no capability.denied event.
  • write_file reaches a read-only mount nested in a writable one the same way (created a file, overwrote reference.txt).
  • Sandboxed run refuses every case variant ("Operation not permitted"): writes, reads and append-opens of the state dir, the kernel files and the nested read-only mount. Seatbelt judges the real file, not the spelling.
  • Every lowercase control is refused (tool_error + capability.denied for the file tools, "Operation not permitted" for run), so the hole is the case alone.
  • Exposed shipped layout: scripts/tui.sh, the README's way to start the TUI, puts the state dir in $ROOT/.aos-sessions/<ts>-<backend> inside the writable --workdir $ROOT, with write_file in the default tools. Workflow runs with --state-dir <workspace>/.aos-state expose it to the writer and benchmarker of the metal workflows. Plain aos run and plain aos-tui use a temp dir and are not exposed.

Not case-related, found on the way (extra): in the scripts/tui.sh layout only the current session's state dir is protected; earlier sessions next to it in .aos-sessions/ are writable by write_file and by sandboxed run, in plain lowercase.

P1, P3, P4 behave as the code says: the denied-write arc gives a tool_error plus capability.denied per refusal; a sandbox refusal inside run is an ordinary tool_result with a nonzero exit and no capability.denied (confirmed); hardlink, rename-in, /tmp, ../, loopback UDP and DNS are refused with the network off (unconfined controls succeed); web_fetch refuses loopback while run curl reaches it.

Nothing was fixed here; the fix is aos code's and the decision the user's.

First Run, on 283a92e

How It Was Run

  • Code: branch claude/competent-heyrovsky-566e83, which contains 283a92e (local main); probes only under reports/least-privilege-probes/, nothing in internal/ or cmd/ changed.
  • Harness (harness_test.go): a throwaway t.TempDir() per world with ws, ref, outside and the state directory (default ws/.aos-state, holding the kernel and artifact stores); tools.Runtime.Protected = [state, state.lock] as cmd/aos and cmd/aos-tui set it; one kernel process per run with the stated grants; a scripted backend that plays the tool calls in order and then exits 0; RunOptions{ContinueOnToolError: true} as agentflow runs; compaction limits raised so every tool message stays in the session. The disk is hashed before every model call, so each attempt's change is the difference between two snapshots (the runtime's own state files and the run scratch dirs are left out; any file named probe* is in).
  • Records: "agent saw" is the tool message in the session, verbatim (paths shortened to <root>, long text cut); tool_error / tool_result is the artifact the runtime recorded for that call; capability.denied is the kernel event attributed to the call through OnCapabilityDenied, cross-checked against the kernel log count.
  • Environment: macOS 27.0.1 (26A434), APFS, case-insensitive (checked: ws/.AOS-STATE stats as ws/.aos-state); Go 1.26.3; /usr/bin/sandbox-exec.
  • Commands, from the repository root, in this order: 
    go test ./reports/least-privilege-probes/ -count=1 -v -run 'TestP1|TestP3|TestP4'
go test ./reports/least-privilege-probes/ -count=1 -v -run TestP2
python3 -I reports/least-privilege-probes/make_tables.py --build
  • History: a first P2 run (commit 21afa55) stopped at c1, the first write that landed, as aos book asked, and reported it. aos book checked c1 against the code and asked for every case; P2 was then rewritten with lowercase controls, the kernel files and the nested mount, and all four probes re-run from scratch for this report.

Caveats

  • A scripted agent issues exactly the calls listed; whether a model would try case variants on its own was not tested.
  • All worlds are throwaway temp directories; no real state directory, session or network address other than loopback (and, in the controls, the system resolver for example.com) was touched.
  • The exposure table is from reading cmd/aos, cmd/aos-tui, scripts/, the shipped workflows and the directory layout on disk; it was not probed against those layouts live.
  • The forged kernel and index entries show write access and that both stores accept the result; what else could be forged (process records, reserved artifact types) was not tried.
