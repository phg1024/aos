Phase 6 Report

Recovery and resume support, mailbox-backed session flow, fully live workflow hardening, and a direct text UI for interacting with an AOS agent.

What Was Done

  • Extended /Users/claw/Code/aos/internal/runtime/runtime.go with resumable checkpoints, recovery into a replacement process, mailbox ingestion, mailbox send/publish/subscribe actions, and block/yield support.
  • Hardened /Users/claw/Code/aos/internal/agentflow/backend.go with raw-response parsing, JSON repair retries, richer action examples, and tool-semantic auto-exit for successful single-purpose writers.
  • Added a direct interactive terminal client in /Users/claw/Code/aos/cmd/aos-tui/main.go that talks to an agent through the resumable mailbox-backed runtime.
  • Moved the live mini-project suite back to the fully live backend path by removing the earlier deterministic coordinator/writer workaround from cmd/aos-mini-projects.

Issues Encountered And Resolved

  • Fully live coordinators previously produced malformed control output often enough to require a deterministic harness. This was addressed by adding raw text parsing plus an automatic repair pass inside the prompt backend.
  • Live writer agents sometimes kept looping after a successful write_file. This was resolved with a generic tool-semantic auto-exit for agents whose only job is successful file writing.
  • The interactive path originally had no clean way to continue an agent session after a yield or a blocked wait. This was resolved by adding resumable checkpoints and recovery-aware run results to the runtime itself.

Decisions Made

  • Mailbox delivery is now treated as part of the runtime session substrate rather than an external demo-only primitive.
  • The text UI uses the same runtime, checkpoint, and mailbox flow as the workflow engine, so it is a real AOS session path instead of a separate chat wrapper.
  • The caveat about deterministic coordinators/writers is now removed for the validated Phase 6 suite, because the mini projects were rerun with the fully live backend path.
