Phase 10 Report

Pressing Esc in aos-tui cancels the running task: the model call, any running shell command, and any delegated agents. The conversation is checkpointed, so the next message continues from there.

What Was Done

  • Runtime. The runtime has a new runtime.ErrRunCancelled error and a RunResult.Cancelled flag. The loop checks the context at the start of each step, right after each model call (discarding whatever that call returned), and after a tool or delegation fails. A cancelled run saves a cancelled checkpoint and goes back to ready, so Resume continues it. Notes tool_cancelled and delegate_cancelled are added to the history so the model knows what was cut short.
  • Tools. Runtime.ExecuteContext passes the context into tools. A cancelled run kills its process group and returns ErrToolCancelled, separate from a timeout. Execute still works for existing callers.
  • Engine. When a delegated agent's run fails or is cancelled, its kernel process is now exited (code 130 for a cancel) and a cancelled trace event is emitted. Before, a failed child stayed active, and any later delegation to the same agent was rejected.
  • TUI. While a run is active, render.WatchEsc switches the terminal to cbreak mode (no line buffering or echo, Ctrl-C still signals) and reads with a 100 ms timeout. A single Esc byte cancels; arrow and function keys arrive as longer sequences and are ignored. The terminal is restored when the run ends or on SIGINT/SIGTERM. The next message starts with a note telling the agent that its previous task was interrupted.

Smoke Run

Run in a pseudo-terminal against a scripted local model server. Esc was pressed while the delegated writer was running sleep 20:

│ writer › run command=sleep 20; echo built
esc: cancelling…
│   ✗ run command=sleep 20; echo built error=tool cancelled: context canceled
└ writer cancelled
cancelled (esc). Your next message continues from here.
you> what happened?

The server saw no further writer call. The coordinator's next request began with the interrupt note. No sleep process was left behind, and the follow-up input was echoed normally.

Decisions Made

  • A cancelled process is parked as ready rather than exited, so the interactive agent keeps its PID and history.
  • A delegated child is closed (code 130) rather than kept around to resume later. When the coordinator resumes, it decides whether to delegate again; the child's files on disk remain.
  • Keys typed while a task is running are consumed by the Esc watcher and discarded.

Known Gaps

  • Esc is only watched on macOS and Linux. Other platforms can only stop a task with Ctrl-C, which quits the TUI.
  • aos run has no cancel key. It can use the same runtime support once it handles signals.

Tests Run

  • make test: all 16 packages pass. go vet ./... is clean. The TUI render package also builds for Linux and Windows.
  • New runtime tests: cancelling during a model call stops at once even with ContinueOnToolError (before this change the loop recorded a backend error and carried on), leaves the process ready, and resumes with earlier work intact. Cancelling during sleep 30 returns in about 0.2 s.
  • New engine test: cancelling during a delegation leaves the parent resumable, exits the child with code 130, and lets the same agent be delegated again.
  • New tool and render tests: ExecuteContext cancellation, lone-Esc detection, and how a cancelled child appears in the progress view.
