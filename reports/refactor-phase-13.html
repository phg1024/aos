Phase 13 Report: Trustworthy Artifacts

Design-review item 5 and the exit-origin follow-up. Artifacts are now tamper-evident, durable across processes, linked into a graph that can be walked from a run's summary, and owned. Agents can no longer publish what looks like a runtime record, resume someone else's checkpoint, or overwrite their own compacted history.

What Was Done

  • Exit origin (4c27580). ExitStatus.Origin is "agent" only for an agent's own exit action, set by the runtime. A verifier failure with that origin stands until the work changes, whatever retryable flag the model chose. Only failures the runtime recorded can be retried.
  • Shared lock (bc97698). internal/filelock (flock on unix) now backs the kernel, the artifact store and cmd/aos's run lock, so ./... builds for Windows.
  • Content addressing. Each index entry records the sha256 of its payload. Every ReadJSON verifies it and returns ErrArtifactTampered on a mismatch. Payloads are written read-only (0444).
  • Durability. Payloads and index.json are written as a temp file and renamed into place, under a mutex plus filelock on artifacts.lock. Artifact IDs come from the larger of the stored counter and the index, so a stale counter cannot reuse one.
  • Lineage. CreateJSON rejects unknown parents (ErrUnknownParent), and, once bound, unknown producers (ErrUnknownProducer). The runtime and engine bind the kernel through Store.BindProducers, so every caller is covered without changing how a store is built.
  • Parent links.
    • Checkpoints chain to the previous checkpoint, or to the checkpoint the run resumed from.
    • Tool results, errors, mailbox records, published artifacts and memory segments name the checkpoint they ran under.
    • A delegate_result names the child's final checkpoint, and an agent_run its own.
    • verification names the verifier's final checkpoint.
    • workflow_summary names every agent_run and the verdict.
  • Reserved types. artifact.IsReserved covers every type the runtime, engine and contract harness produce. publish_artifact refuses those (logging capability.denied) and stores everything else as published.<name>. Its result no longer includes the payload path.
  • Checkpoint ownership. RestoreCheckpoint accepts only checkpoints (ErrNotACheckpoint). Resume and Recover also require the checkpoint to have been produced by the process or by its resumed_from chain (ErrCheckpointNotOwned).
  • Runtime-owned memory. Compaction writes a memory_segment artifact and no longer needs a writable path. MemoryRef.ArtifactID replaces the workspace path, and the read_memory tool returns a process's own segments.

Decisions Made

ChoiceWhy
Producer check bound by the runtime and engine, not by each main.Every run already holds the kernel. Binding at run start covers aos run, the TUI and the demos without changing their construction code.
read_memory needs no capability grant.It returns only the process's own compacted history, which was already in its context, so it grants nothing new. It is limited to segments produced by the process or its resumed_from chain.
Metadata and List do not hash payloads.They return index entries only. Payload contents are only ever read through ReadJSON, which verifies.

Compatibility

  • Index entries without sha256, from before this change, are read without verification. New entries are always hashed.
  • A MemoryRef with only a path (old checkpoints) still decodes. Old .aos-memory files are left where they are.
  • New on-disk items: an index sha256 field, read-only payload files, and artifacts/artifacts.lock.

Known Gaps

  • Tampering is detected but not prevented. An unconfined run can still rewrite a payload (item 8).
  • Legacy entries without a hash are trusted.
  • The lease manager and bus are not yet safe across processes. internal/filelock is ready to use for them.

Tests Run

  • make test: all 18 packages pass. go vet ./... is clean, and ./... builds for Linux and Windows.
  • Artifact store:
    • a tampered payload is detected, and the file is 0444;
    • a crash leftover (stray temp index) and a stale counter break nothing;
    • unknown parents and producers are rejected;
    • an old-format store loads;
    • three subprocesses plus two in-process stores create 125 artifacts, none lost, with gap-free IDs. The same test fails on the old store with a torn index.json.
  • Runtime:
    • a reserved publish is refused and logged;
    • resuming another process's checkpoint, or a tool result, is refused, while a recovered process may use its predecessor's;
    • compaction works without a write path, write_file cannot reach a segment, and read_memory returns only the process's own history;
    • two resumes from one checkpoint keep separate segments;
    • checkpoints and tool results form a chain.
  • Engine: walking from workflow_summary reaches all three agent_runs and their checkpoints, and the verdict with the verifier's checkpoint.
