Path Protection: Case Variants, Symlinked Delegation and Earlier Sessions

Eval's least-privilege probes (717e4b6, reports/least-privilege-probes.html, run against 283a92e) found two holes.

  • Hole 1 (macOS): on a case-insensitive volume, the file tools reached the protected state directory and a nested read-only mount through a path in another case, such as ws/.AOS-STATE or ws/REF. Through it they forged a kernel event and an artifact-index entry, read events.json and processes.json, and wrote and overwrote the read-only mount. Every lower-case control was refused, and so was every variant through the sandboxed run.
  • Hole 2 (any OS): under scripts/tui.sh, earlier TUI sessions sit in the writable workspace, and only the current session was protected. write_file and run wrote into them (probes x1 and x2).

Fixing hole 1's sibling checks in delegation (attenuation) turned up a third problem, which needs no case variant: a scope or mount that is a symlink out of the parent's was granted to a child.

All three are fixed in one commit on top of 283a92e.

Result: go vet ./... and go test ./... are clean. Every new test fails on 283a92e, run with the old code in a throwaway worktree, and passes now. Eval's probes have not been re-run on this commit.

Hole 1: Compare What Paths Name

Cause. Every containment check went through capability.within, which compares two strings with filepath.Rel. This covers:

  • tools.Runtime.protected;
  • the read-only mount veto;
  • scope and mount containment.

filepath.EvalSymlinks, which resolvePath applies first, keeps the caller's spelling. On a case-insensitive volume, two different strings can therefore name the same directory. APFS also ignores Unicode normalization, so even the same letters can be spelled two ways.

Method. within(base, target) keeps the string test. Failing it, target is inside base when target, or one of its existing ancestors, is the same file as base. "Same file" is os.SameFile: the same device and inode. It is stdlib only.

  • Why identity rather than case folding: folding would have to match the volume's rules, which differ per volume and include Unicode normalization. Identity asks the file system itself, so no spelling gets past it, and it is portable.
  • Why every ancestor: a path can reach base at another depth, through a firmlink such as /System/Volumes/Data/Users/… or a bind mount. Once mount containment matches by identity, the protected check must match at the same depths, or it would let those spellings through.
  • Why the string test stays: it is cheaper, and it still answers for paths that do not exist yet.
  • Callers pass resolved paths, so no existing ancestor is a symlink, and identity cannot be fooled by a link.

The fix works in both directions:

  • Refusals now hold however a path is spelled: the protected state directory, its lock and a read-only mount.
  • A case variant inside a granted scope and mount is now granted, where before it was refused.

The check covers all five file tools: write_file, edit_file, read_file, list_dir and find_files. find_files skips a variant while walking.

Cost. When the string test fails, the check makes one stat of base and one lstat for each ancestor of target. The string test fails for every file checked against a root it is not in, such as the protected directory, so find_files pays this for each file it walks.

Attenuation

Excess, intersectScopes, coveringMounts and AttenuateMounts compared the spec's path strings, without resolving them. They were not safe:

RequestBeforeNow
Parent mounts ws (rw) and ws/ref (ro). A child asks for ws/REF writable.Covered by ws only, so the child got a writable mount of the read-only tree, and MountExcess reported nothing.The mount is read-only, and a writable request is an excess.
Parent scope ws. A child asks for ws/link, a symlink to a directory outside ws, as a scope or a mount.Granted as lexically inside. The child's own checks resolve the link, so the child could read or write outside the parent's authority.An excess, and dropped.

Attenuation now compares through contains, which resolves both paths and then applies within. The granted strings are kept as the spec wrote them.

Residual limit: the check runs at spawn. Suppose a parent can write the directory that holds a child's scope or mount. It could replace the scope with a symlink after the child starts, and the child's checks would follow the new link. Closing that needs the child's access to be checked against its grantor chain at use time. That is a larger change, not made here.

Hole 2: Protect the Sessions Directory

Choice: protect, rather than move the default out of the workspace.

  • /resume, aos inspect and the README all point at .aos-sessions. Moving the default would hide existing sessions from /resume.
  • Protection also covers any --sessions-dir or AOS_TUI_SESSIONS_DIR a user picks inside the workspace.

Rule (protectedPaths in cmd/aos-tui), applied to the file tools and to run's hidden paths:

  • The current state directory and its lock are protected, as before.
  • The whole sessions directory is protected, so a session another TUI starts later is covered too. Under scripts/tui.sh that is $ROOT/.aos-sessions.
  • Exception: the sessions directory may hold what the tools must reach. That is the workspace, or the temporary directory where run keeps its scratch. Both can happen with the default sessions directory, which is the state directory's parent: for a TUI with no --state-dir it is $TMPDIR.
    • Then each session found there at start is protected, with its lock, and the rest is not.
    • Limit: in this case, a session created after start, or a directory the agent plants to look like one, is not protected.

Clearer Refusal Reasons (P1c)

The reasons came out of the change naturally, so they are included. A refused path now carries its reason, both in the error the agent sees (path access denied by capabilities: …) and in capability.denied:

  • path is in the protected state directory
  • path is in a read-only mount
  • path outside the granted scopes or mounts

errors.Is(err, tools.ErrPathDenied) still holds, and tools.DenialReason reads the reason.

Not Changed

  • The sandbox's profile. run refused every variant already, and it now also hides the sessions directory.
  • Hard links. A hard link to a file in the protected directory would pass. No tool can make one: the file tools have no link operation, and a confined run cannot reach the source. An unconfined run is outside these checks by design.
  • The time between a check and the open it guards (TOCTOU), as before.
  • Eval's branch, memprobe, probes and patterns.
  • Nothing pushed.
