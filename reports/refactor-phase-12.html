Phase 12 Report: Authority, Real Runs, and Kernel Integrity

Design-review items 3 and 4, plus three fixes found by running a gated workflow on a real model. Delegation can no longer widen authority. Verdicts hold up against re-running the verifier until it passes. Delegated results reach their parents. Kernel state is written only by the Kernel, with the event log as the source of truth and a lock that works across processes.

Item 3: Authority Narrows on Delegation (de0969c, e213f43)

  • Agents declare a delegable set: authority they may grant but not use. Validation rejects any allowed_agents edge wider than the parent's capabilities plus delegable set, naming the edge and the excess. At spawn the engine narrows the child to the parent's kernel record, using DeriveChildSet (now based on path containment) and AttenuateMounts.
  • A single check, authorize, covers every tool call, the delegate action (which needs spawn_agent), and send, publish and subscribe (which need message_agent). Each denial is logged as a capability.denied kernel event.
  • Rasterizer coordinators may write only their ledger and final-summary.txt; the workspace and run are delegable.
  • Path checks resolve symlinks first, so a link inside a mount cannot reach outside it.

Item 4: The Kernel's Rules Hold for Every Writer

  • The store type and its constructor are unexported. kernel.New is the only way in. This is guaranteed at compile time: no other package can name the store.
  • The event log is the source of truth. Each update is one transaction. It writes events first, then the process table, then the cached counters. process.spawned carries the whole record; transitions and exits carry their effect. Each record names the event that produced it in last_event_id.
  • Repair. Every load replays process.* events that are newer than a record's last_event_id. A table left behind by a crash is therefore repaired in kernel.New, and in any other instance reading the directory.
  • Allocation. The next event and process IDs come from the larger of the counter file and what the log and table already contain, so a stale counter cannot reuse an ID.
  • Locking. Each read and update holds an in-memory mutex plus flock on kernel.lock (unix). On other platforms only the mutex applies; this is noted in lock_other.go.

Decisions Made

  • Option (a) from the brief, the event log as a write-ahead log, rather than a single atomic snapshot. It makes the log authoritative and keeps the existing file layout.
  • Old state directories still load. Records without last_event_id were written table-first, so the table is authoritative for them and they are not replayed. Their next update starts the new order.
  • Repair runs on every load, not only in kernel.New. A long-running instance therefore also heals a table that a crashed peer left behind.
  • The run-level lock in cmd/aos (<state-dir>.lock) stays. It still guards the artifact store, leases and bus, which item 5 and later items address. The kernel no longer depends on it.

Known Gaps

  • run is not confined, so a worker can still escape through shell commands (item 8).
  • There is a check-then-use window between resolving a symlink and the file operation that follows.
  • Each kernel update rewrites the whole events.json, as before. A log that only appends would scale better.

Tests Run

  • make test: all 17 packages pass. go vet ./... is clean. Everything builds for Linux. For Windows, ./internal/... builds (the kernel uses the mutex-only fallback), but cmd/aos does not: its own state-directory lock calls syscall.Flock directly. This predates item 4. That lock moves onto a shared, build-tagged internal/filelock helper in item 5.
  • Crash simulation: events are appended straight to the log for a spawn, a transition and an exit, with no table write. kernel.New rebuilds all three, and an instance opened earlier sees the repaired view. Separate tests cover a stale counter and a state directory in the old format.
  • Concurrency: three subprocesses and two in-process instances share one state directory and run 75 spawn, transition, note and exit cycles. The result is 300 events with gap-free IDs, and every record matches its events. With the flock replaced by a no-op, the same test fails.
